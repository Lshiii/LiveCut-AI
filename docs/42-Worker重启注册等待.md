# Worker 重启时的注册等待

2026-11-06：补齐异常退出后的启动接续。Worker 被终止后，本地 journal 锁随进程退出释放，但 Java 中的执行器会话仍可能在 35 秒默认存活窗口内。立即启动同一 worker_id 的新进程时，Java 正确返回 WORKER_SESSION_CONFLICT；新进程需要有上限地等待，而不是首次冲突便退出。

## 启动行为

Worker 默认最多等待 45 秒，只对精确的 WORKER_SESSION_CONFLICT 重试。每次间隔不超过 1 秒，使用单调时钟和可取消等待。未获有效注册回执前不查询待执行阶段、不领取计算，也不调用模型。既有完整 outbox 的幂等回执恢复沿用原协议，不执行新计算。

等待期间持有原 journal 排他锁，同一新 UUID 用于所有注册尝试。新进程不能借用旧 UUID、注销旧持有者或绕过 Java 的会话和槽位检查。正在正常心跳的旧进程会持续保持所有权；超过本次等待上限后，新进程保留冲突原因退出。

CLI 参数为 `--registration-wait-seconds`；PowerShell 启动参数为 `-RegistrationWaitSeconds`。默认 45，允许 0～3600 秒的有限数；0 表示首次冲突直接退出，仍允许一次正常、有客户端截止的注册请求。非法设置在创建 HTTP 客户端之前拒绝，脚本参数校验先于读取私有配置和修改环境。

```powershell
./scripts/worker.ps1 -WorkerId worker-local -RegistrationWaitSeconds 45
```

## 请求截止与取消

注册请求使用剩余启动预算与客户端单次上限的较小值，且在实际网络传输上实施响应截止，持续空白或静默响应不能反复刷新读取等待。注册之外的客户端请求保持原传输路径。系统 DNS 解析仍遵循操作系统行为，不承诺中断系统解析器。

取消检查覆盖等待与注册响应读取，不留下仍在后台发送的注册线程。认证、配置、其他冲突、非法回执及网络故障不被泛化为可无限重试的注册冲突。已获得有效但迟到的成功回执时，不宣告启动完成或领取任务，只清理本进程自己的成功会话。

执行器存活期限从最终成功那次请求的开始时间计算，不能沿用首次失败请求的时间，否则等待旧会话后会立即误判自身过期。正常退出仍由 finally 注销自己的会话；注销错误不覆盖原失败。新会话注册成功不意味着旧阶段租约已释放，领取仍由 Java 的实际占用与 attempt/run_token 隔离。

## 可观察性

CLI 输出 `registration-wait` 和 `registered` 生命周期 JSON。等待事件仅包含 worker_id、已等待秒数与剩余秒数；不输出会话 UUID、鉴权信息或服务地址。`registered` 只在有效回执和本地存活校验之后输出，再进入正常执行循环。

因此启动验收应同时确认新进程存活、它自己的 registered 回执事件、随后持续更新的心跳；只看到 `/api/executors` 的在线快照不足以证明替代进程已启动，该快照可能暂时属于旧会话。

## 验证记录

本地 Python 全量 **1277 项与 98 项 subtests** 通过，Ruff 与 diff 检查通过。独立黑盒验证稳定 UUID、成功请求起算存活期限、精确冲突、取消、journal 排他与回执脱敏。真实本地 HTTP 测试使用 0.15 秒空白流、0.3 秒静默等测试阈值，验证实际截止、读取中取消和 socket 关闭，不把 HTTPX 各阶段超时当作累计时间上限。

PowerShell 7 与 Windows PowerShell 5.1 均通过隔离的 mock uv 启动器测试：4 组合法参数透传、6 组非法参数拒绝，覆盖小数文化格式与环境恢复。CI 在两个 shell 中执行此测试，不读取真实配置、不启动 Worker 或模型服务。

真实 Java 协议使用已完成任务作为只读目标和明确的 QA 执行器：新会话连续遇到两次冲突后，旧持有者正常注销，新会话第 3 次注册成功，只查询一次空队列并注销自己；旧持有者保持在线时，1.2 秒测试预算耗尽后新会话退出，没有查询队列或注销持有者，旧最后心跳不变。

本地还在确认无运行任务后，终止空闲旧 Worker 并立即启动同名替代进程。新进程经历 28 次受限冲突等待后自行注册，随后多次心跳持续更新；进程、它自己的 registered 事件和服务端在线状态同时通过检查，stderr 为空。原分析、人工修订、独立剪辑及导出均保持一致，没有新增模型或 ASR 执行。

上述网络故障和协议状态都是明确的验证场景，不据此推导识别质量或生产吞吐量；公开检查结果以本轮提交的 GitHub CI 为准。
