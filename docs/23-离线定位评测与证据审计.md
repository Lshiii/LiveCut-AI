# 离线商品讲解定位评测与证据审计

2026-10-26。评价未经人工修改的机器预测，不要求商品清单或 SKU；本轮交付评测工具，没有新增真实识别准确率成绩。

## 三种操作

在仓库根目录运行。所有操作只读视频和预测，生成独立文件，不请求 ASR、LLM 或视觉 API，不改 Java 任务、审核或导出状态。

### 生成待标注模板

```powershell
uv run python -m livecut init-annotation data/raw/sample.mp4 --video-id sample_01 --original-video-id source_session_01 --output data/labels/sample_01.json
uv run python -m livecut validate-annotation data/labels/sample_01.json
```

模板绑定实际视频 SHA256、ffprobe 时长和原始场次，初始为 `not_annotated` / `unlabeled`、空范围、空区间。它不是全负样本，不能评分。请在不查看自动预测的情况下记录商品讲解，再声明实际标注来源、范围和状态。

标注 Schema 为 [localization-annotation.schema.json](../contracts/localization-annotation.schema.json)。不记录 SKU，segments 只含参考 ID 和整数毫秒起止。`fully_annotated` 必须声明整个 `[0,duration)`；`partially_annotated` 仅评价明确完成标注的范围。范围须排序、无重叠，相邻范围先合并；每个参考区间完整落在一个标注范围中。

`human`、`agent_assisted`、`synthetic_fixture` 分开保存。只有声明为 test、human 且 independently_reviewed 的参考，报告才标记为“独立人工参考（按标注者声明）”；工具不验证声明本身是否真实。同一场次的重叠录像不能据此变成独立测试集。Agent 辅助核查不能称人工金标准。

### 评分并生成报告

先用可手算的合成示例验证环境：

```powershell
uv run python -m livecut evaluate-localization contracts/analysis-result.example.json fixtures/localization-annotation.synthetic.json --fixture --output-dir data/runs/evaluation-fixture
```

真实输入必须同时提供源视频和生产 SEGMENT / TIMELINE 的 manifest：

```powershell
uv run python -m livecut evaluate-localization data/runs/prediction/analysis-result.json data/labels/sample_01.json --source data/raw/sample.mp4 --prediction-manifest data/runs/prediction/manifest.json --output-dir data/runs/evaluation-real
```

`--fixture` 仅允许两侧都明确为合成数据，不能搭配真实源/manifest。真实校验要求源哈希、媒体时长、视频 ID、job/generation、DRAFT 机器结果、manifest 的源哈希与 analysis_result 文件摘要一致。不会打开 manifest 内声明的任意路径。离线 manifest 只证明这些输入相互一致，不是第三方真实性证明；本轮真实验收另与 Java 已发布 manifest_hash 核对。

输出目录必须不存在，防止覆盖旧报告。生成 `report.json` 和可直接打开的 `index.html`，包括输入摘要、指标、匹配对、带时间的误检/漏检清单和解释边界。报告不复制转写、模型文本、run_token 或本地输入路径。可重复传 `--iou-threshold` 指定预先固定的阈值，默认 0.3 / 0.5 / 0.7。

### 没有参考时只审计

```powershell
uv run python -m livecut audit-localization data/runs/prediction/analysis-result.json --source data/raw/sample.mp4 --prediction-manifest data/runs/prediction/manifest.json --output-dir data/runs/audit-real
```

使用相同来源与预测绑定，只报告内容类型计数、帧时间点和空档。JSON 不含定位评分结果，HTML 明确标记未评分，不输出 Precision、Recall、F1 或边界成绩。采样帧是孤立时间点，不代表连续视觉覆盖。

## 匹配与边界口径

- `product_talk`、`mixed`、`uncertain` 均作为待检讲解候选；只有 `non_product` 排除。此处不评价商品身份、类别归并或返场正确率。
- 原视频整数毫秒、半开区间。每个阈值先求最大一对一匹配数量，再求最大总 Temporal IoU；不使用贪心。Hungarian 权重采用精确 Fraction，匹配数量奖励大于全部 IoU 次级收益，稳定 ID 排序保证输入乱序结果不变。
- 一个预测和一个参考各最多匹配一次，重复候选计 FP。Precision / Recall / F1 同时给出 TP/FP/FN；分母为 0 时记 N/A，不将空样本记为满分。
- 部分标注时，预测与全部已标注范围求交，但保留一个原始 ID 和一个匹配名额；IoU 并集计入其全部可评时间，不能拆成多个 TP。范围外预测单独计数，不当背景。
- 跨未标注边界的匹配仍参与检测，但边界统计标记 censored 并剔除，不能把裁剪后的边缘当作准确预测。其余逐对偏差为预测减参考；汇总取绝对误差的 median / MAE / nearest-rank P90，并报告实际参与数量。

最多每侧 500 区间、输入笛卡尔积 100,000 对、1,000 个标注范围、1～10 个阈值，超过明确失败，不截断。JSON 上限 8 MiB，严格拒绝重复键、NaN、深度/节点超限、bool 冒充整数和未知标注字段；本机源视频上限与上传一致为 1 GiB。

## 验收

Python 全量回归 626 项测试及 98 个子测试通过，无跳过；ruff 通过。新增测试包括独立小规模穷举 oracle：36 组最多 5×5 的区间，各比较 3 个精确阈值，验证最大匹配数及最大总 IoU；另有两种贪心反例、精确阈值、重复候选、部分范围、边界 censored、输入绑定、来源区分和 HTML 转义。

真实 30 分钟开发任务使用原始 SEGMENT 预测，先核对 Java 发布 manifest_hash，再核对文件和实际源视频。生成的未标注模板评分被明确拒绝，修改过的预测被 manifest 摘要拒绝；原文件不变，离线操作期间全部 socket 连接被禁止，连接次数为 0。

审计得到 52 个 product_talk、3 个 mixed、33 个 non_product，这是模型候选数量，不是识别正确数量。现有 16 个采样时间点最后位于 675,009 ms，至片尾最大空档 1,125,008 ms（约 18 分 45 秒）。180 秒时间桶共 11 个，其中 7 个没有观察，含 6 个完整桶及最后 17 ms 余段；这不等于 11 个模型请求窗口。

本轮未修改采样或分类算法，也没有独立人工金标准。因此真实报告保持未评分；合成样例的分数只验证评测器，不能用于简历成绩。真实报告与截图保存在忽略目录 `data/runs/localization-evaluation/`，公开仓库不提交录像、真实转写和标注。
