# LiveCut AI 产品需求文档

> 当前需求已调整为无商品清单自动识别。本文保留立项参考，涉及SKU目录的前置要求由 [最新执行需求](./05-无清单识别需求变更.md) 替代。

v1.0｜2026-10-23｜设计稿。数值为建议验收目标，均非实测结果。

## 1. 产品定义

面向整理直播素材的运营或剪辑人员：上传一段直播回放并提供本场商品清单，系统找出每次商品讲解的位置，将同 SKU 的返场片段组织在一起，展示判断证据，允许修改后批量导出。

核心价值假设：用户先审核系统提出的候选片段，能比从头检索整场直播更快地获得商品素材。这个假设需要通过审核时间对照实验验证，目前没有真实客户或商业需求验证。

通用的长视频转短片已有商业产品，例如 [OpusClip](https://www.opus.pro/)。本项目选择商品清单约束、返场管理和可核查证据作为实现重点，不主张“市场上没有同类产品”。

## 2. 用户与典型故事

主要用户：一人负责一场直播素材整理的电商运营。首版采用单人工作台，不设计团队协作。

典型场景：用户上传 30 分钟回放，商品清单中有抽绳垃圾袋、平口垃圾袋、补水面膜。主播两次讲抽绳垃圾袋，中间穿插闲聊。系统输出三个商品卡片和多次独立讲解；用户确认返场归属，修正一处边界，将两个已确认片段分别导出。

需要保留的异常场景：主播说“刚才那款”、两种垃圾袋外观相近、讲 A 时展示 B、清单外商品、没有明确规格、ASR 漏词、某个模型请求超时。

## 3. 必须统一的业务定义

| 概念 | 定义 | 行为 |
|---|---|---|
| 商品讲解区间 | 连续围绕一个商品进行介绍、演示、报价或相关答疑的语义区间 | 是首版主要定位目标 |
| 视觉出现区间 | 画面中能够看见商品的区间 | 仅作证据，不能直接替代讲解区间 |
| SKU | 具体销售规格，如品牌、尺寸、包装数量组合 | 同类、同品牌不同包装不能自动当同一 SKU |
| 返场 | 同一已确认 SKU 在后面的另一段讲解 | 归于同一商品，时间区间分别保存 |
| 清单外商品 | 有商品讲解证据，但无法对应本场目录 | 显示“清单外/待确认”，仍保留候选片段 |
| 身份不明确 | 多个目录候选均可能，或证据不够 | 显示候选和原因，交人工确认 |
| 音画冲突 | 语音身份与足够清晰的视觉证据不一致 | 标记审核，不自动按画面改写讲解身份 |
| 审核通过 | 用户确认了商品归属和起止时间 | 才能导出正式片段 |

仅有清晰画面而没有商品讲解的静默展示，首版不保证发现。全程没有相关内容的时间段显示为空白背景；不可确定的候选区间单独显示待审核，不能强行填给最近的商品。

## 4. 范围与优先级

### 4.1 M0：先证明核心链路

本地命令行输入一段真实录像和商品 JSON；运行 FFmpeg、真实 ASR、真实文本模型；输出时间轴 JSON 与至少 3 个切片。至少跑一个返场、一个同类不同款或身份不明确案例。保存原始响应、费用记录和失败日志。

Mock 只用于调试接口与 UI；真实处理与回放演示必须明确标识。

### 4.2 M1：可演示 MVP

| 编号 | 功能 | 必须实现的行为 |
|---|---|---|
| P01 | 视频上传 | MP4，建议 15～30 分钟且不超过 1 GiB；上传、校验、失败提示清晰 |
| P02 | 商品清单 | JSON 文件导入与表单修正；sku_id、名称必填，别名/规格建议填，参考图可选 |
| P03 | 创建分析 | 一次提交返回 job_id；重复提交同一幂等键返回同一任务 |
| P04 | 异步进度 | 展示阶段、已完成/总子任务数、失败原因；关闭网页后仍执行 |
| P05 | 商品时间轴 | 商品列表、各次讲解、待审核列表、点击定位原视频 |
| P06 | 证据审核 | 展示相关 ASR 句子、采样帧及风险原因；改商品、改边界、拆分/删除候选、手工新增漏检区间 |
| P07 | 确认与导出 | 只导出当前确认版本；每个区间一个 MP4；失败项可单独重试 |
| P08 | 结果留档 | 原始预测和人工修改分开保存，能导出最终 JSON 和文件清单 |
| P09 | 阶段恢复 | 服务/Worker 重启后基于持久状态续跑；已成功阶段不重复计算 |

拆分通过输入时间点完成；合并首版只允许同 SKU 且连续的片段。多个返场片段以列表管理，不提供跨时段自动混剪。用户可以手工选择起止时间补充漏检片段，记录 origin=manual，不伪造模型预测。

清单外候选可在审核时新增本场商品条目，分配人工商品 ID（本场目录中的 sku_id），并写入审核版本的补充目录快照。人工命名不等于系统核验了外部真实 SKU；identity_source=manual。这个操作不修改运行中分析的目录输入和原始预测。

### 4.3 M2：秋招展示版

- RabbitMQ + Transactional Outbox，沿用同一套 MySQL 任务状态与领取接口。
- 任务租约、心跳、旧结果隔离、有限重试，完成指定故障演练。
- 补齐基础视觉与局部加密策略，对照相同预算的固定视觉方案。
- 一段 120 分钟录像的完整运行与资源记录；支持分块转写的失败恢复。
- 数据集、消融表、演示视频、架构图与可复现实验命令。
- 进度从轮询升级为 SSE 快照推送，保留轮询兜底。

### 4.4 延后

自由规划 Agent、多 Agent、RAG/向量库、模型微调、跨场商品重识别、自动销量/转化预测、抖音等平台发布、自动拉取直播流、复杂字幕/横竖屏重构、会员/支付/多租户、通用 DAG 编辑器、复杂断点续传、Kubernetes。

自然语言交互可在之后增加为“片段查询/筛选助手”。若加入，它只能生成经过验证的筛选条件或待确认操作，不能绕过审核直接覆盖结果或导出。

## 5. 页面与主流程

```text
任务列表 → 新建任务 → 上传与商品清单 → 处理详情
                                             ↓
                                    商品时间轴 / 待审核
                                             ↓
                                  修改并确认 revision N
                                             ↓
                               导出列表 → 预览 / 下载
```

### 新建任务

提供本地视频、商品清单、分析配置和任务预算上限。显示输入时长限制及预计费用状态；未做小样实测前只能显示“待估算”。商品清单更改后生成新版本，不静默改变运行中任务的输入。

### 处理详情

显示“已完成 4/6 个转写块”等真实阶段进度。不将进度包装成预计剩余分钟数。失败时展示可操作的错误类别，如“模型限流，稍后重试”“余额或权限问题”“音频格式不支持”。取消后停止新子任务，正在进行的外部请求仅尽力取消，已发生费用仍记账。

### 审核工作台

左侧商品/返场列表，中间视频与时间轴，右侧证据。待审核原因使用可理解的文字：“规格不明确”“语音与画面不一致”“跨窗口判断不一致”“视觉预算已用完”。不要向产品用户展示数据库锁或 MQ 等实现细节。

系统的高/低风险是审核优先级，不标成“正确率 98%”。模型没有视觉证据时显示“未校验”，模糊时显示“画面不足以判断”。

保存编辑返回新 revision。自动预测边界由 ASR 锚定；人工可设任意合法整数毫秒边界，记录 boundary_source=manual，并保留原始证据。一个商品确认后仍保留原始预测；后续重跑生成新的 analysis_generation，不覆盖已审核版本。

### 导出页

每项展示商品、时间范围、审核版本、状态和下载。批次有部分成功时逐项展示，不把整个批次标成全部成功。用户在导出后继续改时间轴，旧文件仍对应旧快照，可重新创建新导出。

## 6. 用户故事与验收

| 故事 | 验收条件 |
|---|---|
| 我想找同一商品的两次讲解 | 点击商品看到两个独立区间，点击后能跳到正确位置 |
| 我不想误合并两款垃圾袋 | 同类不同规格有独立 SKU；证据不足时待确认 |
| 我想知道系统为何这么判 | 每个自动候选有可定位的 ASR 证据；视觉引用有实际采样时间 |
| 我希望中断后继续 | 关闭网页不影响任务；Worker 被杀后重新领取过期阶段 |
| 我希望修改后导出一致 | 导出绑定确认快照；相同请求不重复生成相同成片 |
| 我不想一直付费重试 | 明确重试次数、视觉上限及任务预算；超限转待审核或可解释失败 |

算法质量和成本门槛由 [评测规范](./04-评测与验收.md) 定义。未达到时缩小输入范围或降级为候选审核工具，不伪造达标。

## 7. 基本约束

首版只在个人本机/个人测试环境使用；视频使用有权处理的素材。密钥只保存在后端环境变量，Git 不提交视频、密钥或临时签名 URL。媒体文件名由服务生成，FFmpeg 使用参数数组调用。

样例规模下先只允许 1 个分析任务活跃运行；文本/VL API 和转码各自限并发。MVP 建议测试机器有 16 GB 内存与至少 20 GB 可用磁盘；这是资源规划起点，不是已测最低配置。长视频展示样例额外预留空间，磁盘不足时在开始阶段提示。

## 8. 作品交付清单

可运行仓库、锁定依赖、环境变量示例、样例清单、合成接口 Fixture、真实运行报告、标注规范、自动预测/人工结果对照、故障演练记录、约 3 分钟演示视频。

首轮演示顺序：商品返场定位 → 解释一处错误与修正 → 导出 → 重启恢复 → 查看质量/费用报告。比展示很多空页面更能说明项目能力。
