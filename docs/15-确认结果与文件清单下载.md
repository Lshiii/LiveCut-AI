# 确认结果与文件清单下载

该功能补齐 MVP 的 P08 留档入口。原始模型预测继续独立保存；下载的审核文档使用独立格式，不冒充原始分析 Schema 2.0。

## 页面操作

审核区的“留档版本”选择已确认修订，点击“下载确认版本 JSON”。当前页面可以是较新的草稿，下载仍绑定所选历史确认版本。存在未保存修改或正在提交时，下载按钮禁用。

正式导出区选择一个批次，点击“下载文件清单 JSON”。清单记录该批次当前状态，部分失败如实列出；只有成功片段带文件名、大小、SHA256 和相对下载地址。单项 MP4 下载继续使用原来的入口。

## API 与文档格式

| 请求 | 行为 |
|---|---|
| `GET /api/jobs/{id}/review/download?revision=N` | revision 必须明确指定且已确认，返回 JSON 附件 |
| `GET /api/exports/{id}/manifest` | 返回该批次带 state_version 的文件清单附件 |

审核附件为 schema_version=1.0、data_kind=review_revision，包含 job_id、video_id、analysis_generation、revision、review_status=CONFIRMED、原确认时间、时长、商品与片段。片段保留 origin、boundary_source、identity_source、original_prediction_id 等来源字段。

`source_video_sha256` 是上传视频的内容哈希；`prediction_source_sha256` 是初始化审核时验证并保存的原始预测文件哈希。两者不能混用。文档不包含最新修订号、其他已确认版本列表或下载时间，因此后续草稿和其他版本的确认不会改变该版附件字节。确认时间按应用已有的 UTC 数据库会话格式化，不依赖 JVM 默认时区。

文件清单为 schema_version=1.0、data_kind=export_manifest，包含冻结的确认版本、generation、源视频哈希、snapshot_hash、编码配置，以及当前批次状态、state_version 和逐片段状态。成功项的 file 包含 filename、size_bytes、sha256、download_url；其余项 file=null。清单包含执行状态，是明确版本的状态快照，不是逐条历史事件，也不是内部 Worker manifest。

读取时先锁分析父任务，再锁导出批次，保证状态与版本一致。成功文件复用内容 GET/HEAD 的 manifest 与实际字节完整性检查；文件缺失或篡改时明确报错，不生成含虚假可用文件的清单。清单使用创建批次时冻结的数据，不读取最新草稿。

两个附件均使用服务生成的 ASCII 文件名，响应带 Content-Length、精确附件字节的 SHA256 ETag、no-store 和 nosniff。前端保留服务器原始响应字节下载，非成功响应按结构化错误显示，不把错误 JSON 当文件保存。附件不包含本地路径、对象存储 key、Worker 凭证或原 Provider 响应。
