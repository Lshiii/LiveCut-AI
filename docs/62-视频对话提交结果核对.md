# 视频对话提交结果核对

## 用户问题

当前 Agent 提问超时后，只在单个 localStorage 槽保存 key/input，组件还优先读取 mount cache。另一页可覆盖该槽；原页重载后更改问题或预算会生成新 key。若原请求已完成，新 key 可能再次建立相同轮次、占用模型预算。不能把“未收到响应”当作“服务端未收到”。

本轮优先修复这一交付可靠性问题，问答笔记导出留待后续。保留单视频工具、原模型预算、原问题与已完成回答，不新增 ASR、模型调用或 Worker 能力。

## 原提交只读查询

- `GET /api/jobs/{jobId}/agent-session-submissions/{key}`：按原 Idempotency-Key 查已创建的 VIDEO 会话，返回既有 Session 形状。
- `GET /api/agent-sessions/{sessionId}/turn-submissions/{key}`：按原 key 查该 VIDEO 会话中的原轮次，返回既有 Turn 形状。

接口沿 analysis → session 的锁顺序，只 SELECT。不存在分别返回明确业务 `404 AGENT_SESSION_SUBMISSION_NOT_FOUND` / `404 AGENT_TURN_SUBMISSION_NOT_FOUND`；其他 owner、CAPTION kind 或不一致的请求指纹必须拒绝，不暴露其内容。key 沿用既有字符及长度约束。查询不创建会话、轮次、阶段、调用预留或模型请求；返回形状不增加 key、私有路径或凭证。

## 本机回执与跨页保护

每个未决提交使用独立不可变 entry，包含版本、kind、原 key、job/video/视频 hash、session（轮次提交时）、完整原 input。新 entry 写入并复读成功后才能发出 POST；不能用一个新 key 覆盖另一页的未决 entry。恢复时扫描本任务记录，而不是优先信任 mount cache。多个页面的独立 entry 即使同时存在也都保留，禁止新建请求，逐项核对；只删除本次确切匹配的记录，不删除他页或后续记录。

另一页移除 entry 不代表本页已确认收到业务结果。本 mount 已知的 UNKNOWN 身份仍保留到按原 key 核对完成，不能因外部槽消失又生成新 key。扫描、storage 事件及离开前应把仍未核对、外部缺失的 entry 按原 key/body 确保持久并复读；失败时保留离开保护与回执下载入口，不只在内存保留后任其刷新丢失。独立 entry 保证并发操作的身份不被互相覆盖，并不宣称跨页面绝对 single-flight；同时产生的不同操作须全部保留并逐一核对。

本页只钉住自身实际提交或主动开始核对的操作，被动观察的其他页 entry 不自动复写。若本页已经严格收到该完整操作的结果，另一页又因尚未收到回执而复写同一 entry，本页可依据仅存于当前 mount 的完整 ACK 事实继续使用；UI 和新请求前后扫描须一致过滤。ACK 不从 localStorage、导入文件或列表同文字恢复，不自动删除另一页重现的 entry；不同 key、同 key 改 input/owner/source 都不能过滤，避免跨页反复删除与复写。

原单槽 SESSION 回执以及当前已读取会话的旧 TURN 回执，在核对 owner 后迁入独立 entry，保留原 key/body。复制成功并重新比较原槽未变才清原槽；坏记录、存储错误或来源不一致不能被静默当作“没有回执”，也不能自动换 key。

未决提交与未发送问题是独立状态。允许保留和修改本页草稿，但新对话/新提问必须等待原提交核对；修改预算不代表授权替换原请求。页面展示原问题、原次数上限及「核对原提交」，必要时可下载原回执留档。

## 恢复流程

用户明确点击核对后，先 GET 原提交。仅精确业务不存在时，才允许按原 key、原 input 重试 POST；该 404 不证明迟到原请求永远不会完成，不能换 key。通用 404、网络失败、坏响应或来源/问题/预算不一致均保留原记录，不发新 POST。

核对成功会话或轮次后，严格解析 owner/source/问题/原预算，采用既有业务结果，并 CAS 清本条回执。会话核对完成不自动继续提问；轮次核对也不自动建立另一轮。若用户已编辑其他草稿，保持其文字和预算，不用旧回执覆盖。已成功、失败或取消的原轮次仍是原提交的结果，不能因为没有回答而偷偷重建一次。

隐藏、跨任务、卸载及迟到回调不能覆盖新页面或清除未决记录。写请求不随只读刷新取消；恢复读取与原提交识别不能靠列表中“相同问题文字”猜测。旧服务没有只读路由时保留回执，提示更新服务，不能降级为直接重新提问。

唯一新增的未落库终态出口针对已满 100 轮的会话：本次精确原 key/body POST 明确返回 `409 AGENT_SESSION_LIMIT` 后，再 GET 原 key 仍为对应业务不存在，且 fresh GET 严格同 owner/source 的完整 Session 确有 100 轮，才可显示「解除此条未提交记录」。服务端在同锁内先查 key、再判单调轮数，且没有删除轮次接口，因此迟到原请求也不能再落库。原回执继续保留供下载；用户明确点击解除时再次核验原记录和完整会话，再仅删除本条确切匹配 entry。不能自动新建对话或提问，也不能把暂时 BUSY、网络失败、通用 404、坏响应或来源不符当成此终态。

## 验收

Java 集成覆盖真实 MySQL 上的两个只读查询、提交前/后查询、同 key 重试、跨 owner/kind 拒绝、坏 key、请求指纹不一致、行数与原预算不变，以及已满 100 轮时既有 key 仍可找回、缺失 key 拒绝且不增预算的对照。前端覆盖多页不同 entry、原槽迁移、存储失败不 POST、修改草稿/预算不换原 key、只认业务 404、丢回执成功找回、外部删除后重新持久并重载恢复、迟到与切任务、成功/失败/取消结果核对、原输入保留及 LIMIT 严格显式解除。

浏览器使用明确的受控 HTTP fixture 模拟回执丢失、业务/通用 404 与跨页恢复；真实服务优先用既有成功会话的原 key 做 GET 验收，不为测试新增模型请求。原始素材、数据库、凭证和私有回执不提交仓库。技术检查不代表付费意愿已经得到验证。
