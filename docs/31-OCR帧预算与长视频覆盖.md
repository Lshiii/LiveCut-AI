# OCR 帧预算与长视频覆盖

2026-10-28，新增随任务冻结的 `ocr_max_frames`，解决 90 分钟实测中固定 16 帧过于稀疏的问题。新 API / 工作台任务默认上限 120 帧，可设为 1～120 的整数；历史任务缺字段时仍按 16 帧执行，不更改其配置、哈希或已发布预测。

本轮真实运行只验证 OCR 证据、预算传递和恢复，没有重新调用语义模型。原 90 分钟的 215 段预测和三段成片继续属于旧 16 帧配置，不能把它们描述成 120 帧方案的识别结果。

## 配置与兼容

```json
{
  "video_id": "已有视频 UUID",
  "config": {
    "visual_provider": "ocr",
    "ocr_sampling": "uniform",
    "ocr_max_frames": 120,
    "max_text_calls": 100,
    "max_asr_submissions": 1
  }
}
```

Java 将帧预算写入 config_json / config_hash 和阶段输入身份，领取、重试均使用冻结值。拒绝 Boolean、小数、字符串、null、0 和超过 120 的值。Worker 在 OCR 分支传递该值；语音模式不执行 OCR。页面显示实际保存的上限，旧任务显示原 16 帧；选择语音模式时不显示或提交无效的 OCR 预算。

创建幂等兼容按锁内旧记录的配置形状判断：只有请求省略某字段、旧记录也缺该字段，才从兼容候选中移除它并重算旧请求摘要。`ocr_sampling` 和 `ocr_max_frames` 分别处理，因此早期缺两字段、旧 uniform / prefix 缺预算字段的回执都可恢复。显式字段、视频或其他配置不同仍返回 409，DuplicateKey 竞争恢复使用同一规则，不回填旧记录或套用其值来放宽请求比较。

采样函数和缓存格式保持不变。uniform 仍取 `min(max_frames, ceil(duration_ms / 45000), duration_ms)` 个等宽时间桶中心；新增预算直接参与已有 OCR 状态和 cache key，因此 16 / 120 帧不会互相误命中，同一输出目录也不能静默换预算。CLI 原缺省 16 帧保留，使用已有参数显式加密：

```powershell
uv run python -m livecut ocr data/raw/sample.mp4 --output-dir data/runs/ocr-120 --cache-root storage/cache/ocr-v1 --ocr-sampling uniform --max-frames 120
```

120 是上限，短视频不会为了凑数反复采样。增加帧数会增加本地计算，也可能增加后续文本输入 token；它不是整个模型费用预算，更不代表连续视觉核验。视频存在极短尾窗时仍可能没有采样，例如 5,400,001 ms 最后的 1 ms 窗口，必须继续按实际 PTS 审计。

## 配套容量保护

120 帧按每张最大 4 MiB 加元数据保守预留约 484 MiB；旧默认 512 MiB 在已有缓存超过约 28 MiB 时会拒绝新构建。因此共享 OCR 缓存默认总上限调整为 **1 GiB**，条目上限仍为 128；显式较低配额继续生效，容量不足明确失败，不自动删除旧缓存、不重跑或改变证据。该配额约束磁盘缓存，不代表一次性把全部图像载入内存。

测试模拟已有 32 MiB 占用：显式 512 MiB 配额在 OCR 开始前拒绝，新的默认配额允许完整 120 帧构建并保留旧占用。命中完整且通过验证的缓存仍不需要新的构建预留，原容量与完整性保护继续生效。

这些数字只证明本素材的证据时间分布更密。OCR 仍只读画面文字，不能据此看懂服装外观；短暂展示仍可能漏过，没有转写邻近证据的帧也不会自动进入语义输入。没有人工 gold、准确率、Temporal IoU 或剪辑质量提升结论。

## 真实 API / Worker 恢复

服务加载新代码后创建独立零模型预算任务 `227005da-d92c-423b-921a-a656f2de3238`，不显式提供帧预算，实际冻结为 uniform / 120。MEDIA 正常完成，ASR 按既有协议复用同视频已验证转写，没有新提交。

SEGMENT attempt 1 在正式共享缓存中真实生成 120 帧，然后因预设文本预算为零返回 `BUDGET_EXHAUSTED`；正常 retry 的 attempt 2 命中同一缓存，仍因零预算失败。两次 OCR 状态、帧和观察完全一致，MEDIA / ASR 成功阶段不变，模型账本为零行。两次阶段 wall 为 54.640 / 2.750 秒，包含 Worker 协议开销，不代表完整语义分析耗时。验收任务最后正常取消收尾。

另用原 90 分钟任务的创建键重放原请求，返回字节完全相同，配置仍没有新增字段。服务更新、Worker 验收与回执重放后，原 52 个公开资源和基线 1,407 个文件摘要全部不变。此处既有缓存和已发布证据均保留，没有淘汰操作。

本地证据位于忽略目录 `data/runs/ocr-frame-budget/`，包括 OCR producer / 独立审计、零预算 Worker、账本、旧回执和资源保留报告。真实图像、OCR 文本、配置凭证和模型权重不提交。
