# 字幕校对与素材包

2026-11-07。目标是让用户从已确认成片继续完成字幕校对，取得可交付文件。这是产品价值假设，尚无本项目真实付费或效率对照证据。

## 用户流程

已完成 MP4 → 校对字幕 → 回看成片、修正文案和相对时间、核对被裁断原句 → 保存新修订 → 明确确认 → 下载 SRT / VTT / TXT / JSON 或 MP4 与字幕素材包。原 ASR、话题审核、按需方案和旧 MP4 保留。

[Descript](https://www.descript.com/tools/video-caption-generator)公开提供可编辑转写、字幕文件和带字幕视频；[OpusClip](https://www.opus.pro/tools/video-to-srt)公开提供 SRT 和文字稿下载。这支持优先完善字幕交付，但不能用竞品能力证明本项目用户愿意付费。

本版 ZIP 含干净 MP4 与独立字幕文件，视频没有烧录字幕。后续仍需完善字幕样式、烧录和真实用户任务验证，不能描述为已经覆盖所有平台发布需求。

## 时间与来源

- 字幕为成片相对整数毫秒。逐个冻结 parts 与原句求半开区间交集，再累计前面保留区间的长度。删除区间不生成字幕，保留区间内的静默不压缩。
- 例如保留源 [10s,15s) 和 [30s,34s)，源 [31s,32s) 映射为成片 [6s,7s)。不能用首尾包围区间代替拼接时间轴。
- ASR 只有句级时间。句内裁切保留全文作为校对依据并标待核对；用户明确复核或删除该 cue 后才能交付，改文本不自动复核，不能按字符比例猜词时间。
- timing_basis 固定 SOURCE_EDL_SENTENCE_MS；另显示已验证媒体元信息中的实际成片时长。编码有帧/音频容差，旧成片没有逐接缝 PTS，不宣称样本级或词级精准。
- 初始化验证 MP4 manifest/SHA256 及原任务已发布 ASR，核对审核或按需请求冻结原句；绑定 export snapshot、clip hash、transcript hash、parts 和算法版本。后续不扫描“最新转写”。

## 修订与人工确认

V15 新增 caption_document、caption_revision、caption_confirmation。保存提交当前 base_revision，新版本不可变；确认需 acknowledge_review=true 且没有待核对 cue。空字幕允许显式确认：SRT/TXT 零字节，VTT 保留头。

用户只能编辑 cue 正文、相对时间、reviewed 状态或删除 cue，不能伪造来源、原始 partial 标记和 ID。r0 保留审计依据；新草稿不覆盖历史确认版本。

字幕草稿加入父工作台的换任务保护；换片或关闭需先处理草稿。隐藏播放器暂停。当前草稿可本地预览，服务器下载只接受明确的确认版本。

## API

基路径为 /api/exports/{exportId}/clips/{clipId}/captions。

| 方法 | 路由 | 用途 |
|---|---|---|
| POST | 基路径 | 幂等初始化 |
| GET | 基路径，revision 可选 | 当前或历史修订；未初始化 404 |
| PUT | 基路径 | base_revision 和 cues，每项仅 id/start_ms/end_ms/text/reviewed |
| POST | /confirm | revision 和 acknowledge_review=true |
| GET/HEAD | /files/{format}?revision=N | 已确认 srt/vtt/txt/json；ETag 为实际附件字节 SHA256 |
| GET | /package?revision=N | 单片 MP4 与字幕 ZIP |
| GET | /api/exports/{exportId}/package?items=clipUUID.revision,... | 显式多片，原生浏览器流下载 |
| POST | /api/exports/{exportId}/package | items 数组：clip_id/caption_revision |

最多 100 个不重复成片；每个选中项都必须成功、完整且字幕已确认。任一项缺失、损坏或未确认时失败，不静默漏件。页面“本批素材包”要求该批全部成片及字幕准备完毕。

## 文件与资源

- 每片目录含 MP4、SRT、VTT、TXT、确认字幕 JSON；根目录含 README 和逐文件大小/SHA256 的 manifest。
- 交付 JSON 只有确认正文和公开来源标识，没有被删原文、全片 ASR、私有路径或供应商响应。
- 三种文本格式共用同一确认版本。文本转义与换行处理防止原文标签、空行或箭头破坏字幕块。
- MP4 固定缓冲复制，同时再次验证大小/SHA256；完整 ZIP 构建通过后才发送成功响应。打包和网络发送不持有业务行锁。
- 默认总输入最多 2 GiB、并发准备/下载 2 个、暂存配额 4 GiB、构建 180 秒、网络发送 10 分钟；进行中的字节配额和槽位持续预留。完成/断连清理，15 分钟兜底回收未消费文件。
- 可配置 LIVECUT_CAPTION_PACKAGE_MAX_BYTES、LIVECUT_CAPTION_PACKAGE_SLOTS、LIVECUT_CAPTION_PACKAGE_TEMPORARY_QUOTA、LIVECUT_CAPTION_PACKAGE_BUILD_SECONDS。大包不放入 JVM 或前端 Blob 内存。

## 验收关口

纯测试覆盖整句/截断、删除中间句、同句跨 parts、相邻区间、静默、空字幕、毫秒与溢出，以及非 ASCII、小时以上时间、换行标签和空文件。领域测试覆盖来源/内容哈希、并发冲突、历史确认、partial 不可绕过、严格字段和混合包拒绝。

真实验收使用已有单段课程成片及两段 KV Cache 拼接成片：逐 cue 核对原句和相对偏移，回看字幕、下载文本与 ZIP、重算包内 SHA256；原分析、ASR、审核、剪辑和旧导出应保持原状。技术通过不代表独立准确率或商业验证。

## 本轮实际结果

- Java 完整 Verify：285 项通过、0 跳过；包含 19 项映射/格式、12 项 ZIP/配额/逐片加载和 11 项 MySQL/HTTP 字幕集成。前端 140 项、类型检查及生产构建通过。
- 真实课程两个成片生成 19、40 条字幕；逻辑时长 128556、229843 ms，媒体元信息分别 128584、229875 ms。原 MP4 SHA256 与旧导出完全相同。
- KV Cache 成片保留源 [8572,31315)、[178900,188442)，三条字幕映射为 [0,9797)、[9797,22743)、[22743,32285)。实际媒体元信息 32334 ms；这个差异未被用来按比例拉伸字幕。
- 三份 r0 都没有句内截断；句内裁切与待核对阻断由合成领域样本验证，没有把不存在的真实边界风险写成实测。
- 开发 Agent 对照既有 ASR 与时间映射确认了三份字幕用于下载验收，未逐句独立听音，也未测 ASR 准确率。课程首段先确认 r0，再去掉首条字幕末尾空白、保存并确认 r1；旧 r0 的原生 SRT 下载仍可用。
- 三个单片 ZIP 与两个显式批次 ZIP 均完成实际下载；逐项重算大小/SHA256，MP4 与旧成片一致，交付 JSON 没有 source_text 或私有 transcript_key。课程双片包 12265030 字节、12 个文件；KV 单片包 673064 字节、7 个文件。文件数包含根清单及 README。
- 真实浏览器走通普通导出和按需剪辑两个入口、未确认整批阻断、编辑/无效时间草稿的关闭保护、放弃恢复、删除撤销、修订确认、旧版本下载、批量准备与点击下载。下载保留原工作台。320×800 时编辑层 304×784，没有横向溢出，底部操作保持可见。
- 验收暴露并修复了 MySQL JSON 数字节点导致的误拒绝，以及 Vue Proxy 不能被 structuredClone 复制的问题；两者均重新通过实际路径。修复后的浏览器操作无新增控制台错误。
- 原分析、审核、剪辑、会话及旧导出共 8 个公共资源与基线相同；本轮未外发模型或 ASR 请求。V15 已在本机服务应用，执行器已恢复在线。

本机证据位于忽略目录 data/runs/caption-delivery；日志、真实转写、下载包和截图不提交公共仓库。尚未验证多用户商业部署、真实付费意愿、平台端字幕兼容性矩阵或字幕烧录效果。
