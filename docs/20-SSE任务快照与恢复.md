# SSE 任务快照与断线恢复

2026-10-25 开发，2026-10-26 完成联合回归与本机真实浏览器验收。

## 目的与范围

在现有 Java/MySQL 业务状态和公开快照上增加分析任务、导出批次的 SSE 展示。Python 的领取、租约、模型账本和产物协议不变；连接建立、断开、重连均不创建任务或调用模型。上传仍使用独立的持久分片协议。

本轮采用服务器按资源共享读取当前状态，再向浏览器推送完整快照。它恢复的是最新可见状态，不是逐条历史事件重放；暂不增加事件表、MQ 或 Outbox。未订阅的资源不持续读取，同资源的多个连接共享一次轮询结果。

## 固定协议

- `GET /api/jobs/{id}/events`：`text/event-stream`，数据与原 `GET /api/jobs/{id}` 的公开 `JobSnapshot` 相同。
- `GET /api/exports/{id}/events`：相同媒体类型，数据与原导出批次详情快照相同。
- 业务事件类型为 `snapshot`，`data` 直接包含完整 JSON，无额外包裹。
- `id` 为 `job:<UUID>:<state_version>` 或 `export:<UUID>:<state_version>`；它是资源版本标记，不是跨资源或历史事件序号。
- `retry: 2000` 提示通用 EventSource 客户端的重连间隔；空闲连接使用注释心跳。
- 响应包含 `Cache-Control: no-cache, no-transform` 与 `X-Accel-Buffering: no`。不存在/非法资源以及容量超限，在流提交前沿用现有 JSON 错误与请求 ID。

每次连接都重新读取当前完整快照，包括浏览器携带旧、相同、较新或不可信 `Last-Event-ID` 的情况。该字段不授予资源访问权，也不令服务器跳过初始补状态。页面自身按资源 ID 和 `state_version` 接受更新，较旧版本不能覆盖较新版本；同版本允许更新当前运行配置派生的操作提示。

分析终态为 REVIEW_READY、FAILED、CANCELLED；导出终态为 SUCCEEDED、FAILED、PARTIAL_FAILED、CANCELLED。服务器发送最终完整快照后释放连接。用户重试使任务重新进入活动状态后，页面建立新订阅。

## 并发与资源边界

注册订阅后读取初始状态，后续共享扫描补充变更，避免只发送一次旧初始状态。数据库事务结束后才进行网络发送。每连接仅保留一个待发送的最新快照，允许合并中间展示状态；不宣称每次中间迁移都会到达浏览器。

连接数、同资源连接数、发送线程和待执行发送均有上限。慢连接不能阻塞共享读取线程；超时、发送失败、客户端断开与服务关闭需幂等回收登记和配额。默认共享扫描周期 1 秒、注释心跳 15 秒、流生命周期 120 秒；以最终配置实现和验收为准。

## 客户端

使用 EventSource 接收完整状态，收到有效且归属匹配的快照后才显示实时已连接。断线后关闭旧连接、退避重连，保留最后有效快照并启用 HTTP 轮询兜底；浏览器不支持 EventSource 时继续使用轮询。

任务切换、终态和组件卸载关闭连接及重连计时器。旧连接、迟到回调和旧 HTTP 响应不能覆盖新任务。SSE 不重载审核内容、不丢弃未保存修改，也不重置导出选择或视频预览。列表和详情的 HTTP/SSE 结果使用同一版本合并规则。
