# OCR 高帧结果发布

2026-11-12。修复开启本地 OCR 的长视频在分析结束后，仍可能因结果文件数超过 Java 通用上限而无法发布的问题。默认工作台仍使用语音转写；本次不改变模式选择、采样预算或模型提示词。

## 问题与复现

Worker 的普通 `SEGMENT` 阶段会将分析结果、OCR 来源记录、观察文字、帧索引、状态、每张 JPEG 和可选文本执行轨迹一起写入当前 attempt 的 manifest。N 帧对应 **N + 5** 项，有执行轨迹时为 **N + 6** 项。Worker 支持最多 120 帧，但 Java 原来统一只接受 64 项。

例如 120 帧加执行轨迹实际有 126 项。文件和模型输出即使已经生成，完成回调仍会收到 `INVALID_MANIFEST`。原编译版本的独立探针已复现：58 帧加轨迹的 64 项通过，59 帧加轨迹的 65 项、120 帧的 125/126 项被拒绝。

45 秒间隔、帧预算足够时，采样数为 `ceil(duration_ms / 45000)`，再受预算约束。有轨迹时，时长严格超过 43 分 30 秒即可达到 59 帧并越界；无轨迹时，严格超过 44 分 15 秒达到 60 帧。低预算任务不一定触发；不能把所有长视频失败归为此原因。

## 放行规则

保持旧清单 ≤64 项的现有行为。只有**普通分析 SEGMENT** 的清单超过 64 项时，才进入单独的完整 OCR 结构校验，总数最多 126 项。

| kind | 当前 attempt 下的固定相对路径 | 要求 |
| --- | --- | --- |
| `analysis_result` | `analysis-result.json` | 必须存在 |
| `ocr_cache_provenance` | `ocr/cache-provenance.json` | 必须存在 |
| `ocr_observations` | `ocr/observations.json` | 必须存在 |
| `ocr_frames` | `ocr/frames.json` | 必须存在 |
| `ocr_state` | `ocr/ocr-state.json` | 必须存在 |
| `ocr_frame_000001` … `ocr_frame_000120` | `ocr/frames/ocr_000001.jpg` … `ocr/frames/ocr_000120.jpg` | 从 1 连续编号，最多 120 个 |
| `text_execution_trace` | `text-execution-trace.json` | 可选 |

不接受缺元数据、跳号、重复 kind/key、额外类型、改名路径或第 121 帧。MEDIA、ASR、TIMELINE、Agent、剪辑与导出等其他类型仍保持 64 项限制。现有来源身份、当前租约及 attempt/token、目录约束、符号链接拒绝、文件存在性和 SHA-256 校验继续执行；这次只调整特定清单的容量准入。

Python 的离线评估 manifest 绑定层同步采用该例外，避免已发布清单随后被旧 64 项检查误拒。此绑定检查本身不读取被引用文件，也不新增话题质量评测；MEDIA/ASR 复用清单的限制不变。

## 兼容与恢复

无需新增配置、数据库迁移、Worker 协议或提示词版本。已有 Worker 发出的完整清单可以由修复后的 Java 接收；不会改写旧 manifest、缓存或已发布结果。

不会自动复活旧失败任务、增加模型预算或清空账本。需要继续旧任务时仍使用现有明确的重试流程，并分别核对已完成 ASR、OCR 缓存和文本检查点。`UNKNOWN` 请求仍不能当作未调用而重发。此次没有实现普通分析的任意结果离线恢复，也不保证任何旧失败重试都零成本。

## 90 分钟真实素材的受控发布验收

在独立数据库与存储副本上创建新任务 `bd64eb4d-1c3c-4eac-b15a-5c0b1d7d6cf8`，复用同视频已有的 756 句 ASR，使用当前生产 Worker、真实 FFmpeg / RapidOCR，以及本地 `httpx.MockTransport` 合成语义响应。模型名和话题标题明确标记为合成；不修补生产 executor、话题解析或缓存函数。网络只允许本次本机 Java API，供应商地址不出网。

| 阶段 | 本次观察耗时 | 实际行为 |
| --- | ---: | --- |
| MEDIA | 3.730 秒 | 处理原 90 分钟视频 |
| ASR | 1.043 秒 | 核验并复用已发布转写 |

Java 实际接受完整清单，SEGMENT 完成回调往返为 0.456 秒。隔离账本新增 **9 行合成文本调用**，真实供应商、ASR 与 embedding 请求均为 **0**。耗时来自单次开发机器运行，语义模型是本地合成响应、ASR 是复用，不能拿这些数字表示真实模型处理整段视频的速度。

视频 SHA-256 为 `ae19e9a58068fba8eec1840b0387174f93a53f805cce824024c3d49ff9d9eded`。原 120 帧缓存的 123 个产物已只读验证，旧 JPEG 共 3,217,900 字节；但其抽帧身份为 `copyts-showinfo-v1`，当前生产为 `copyts-showinfo-v2-exact-pts`，因此没有伪称命中。原缓存保留，在隔离副本上真实重建当前版本，抽帧与识别 55.328 秒、包含校验与恢复材料生成的缓存调用 60.657 秒。随后独立输出目录再次调用生产缓存函数，命中并恢复 120 帧，耗时 2.874 秒；这不是第二次模型请求或业务重试。

初次运行误用了缺少 `jsonschema` 的系统 Python，在注册与领取前终止，日志保留；切换已有正确 `.venv` 后，业务任务每个阶段均只执行一次。没有清预算、复活旧任务或覆盖原预测。历史 215 段预测继续属于旧 16 帧配置，本次合成话题不能当作新的真实识别效果。
