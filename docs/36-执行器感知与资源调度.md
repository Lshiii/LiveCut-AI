# 执行器感知与资源调度

本轮解决实际出现过的情况：Java 可以接收并保存解析任务，但 Python Worker 没有运行，页面只能显示“等待执行”，无法解释原因。

## 执行边界

Java 继续作为业务状态唯一写入方。Python Worker 主动领取阶段并执行 FFmpeg、ASR 和文本分析，通过内部接口续租、提交结果。现有阶段租约、`attempt + run_token`、持久请求账本、预算和未知调用恢复规则保持有效。

独立执行器心跳与阶段续租分开：前者在空闲和工作期间都运行，用于观察执行器是否在线；后者维持当前阶段的执行资格。执行器在线超时不直接使任务失败，也不直接释放仍有效的阶段租约。

## 内部协议

以下接口沿用内部 Worker 鉴权，不向前端暴露密钥或执行凭证。

| 接口 | 请求与行为 |
|---|---|
| `POST /internal/workers/register` | `worker_id`、本次启动的 UUID `session_id`、`stage_types`、`slots`、可选 `target_job_id`；相同会话与配置幂等，在线同名异会话拒绝 |
| `POST /internal/workers/heartbeat` | `worker_id`、`session_id`；执行器空闲时也上报，服务端时间作为最后可达时间 |
| `POST /internal/workers/unregister` | 正常退出时停止领取；不清除仍有效的任务租约，旧会话不能关闭已替换的新实例 |
| `POST /internal/stages/claim` | 原领取协议增加 `session_id`；校验在线状态、能力、目标任务及容量，容量不足返回 `NO_CAPACITY`，不增加阶段执行次数 |

每次进程启动使用独立会话。已过期或注销的会话不能用迟到心跳复活；同名执行器重启后，旧心跳不能覆盖新会话。正常退出会尝试注销，进程崩溃由心跳超时反映。

Python 当前每个执行循环只有一个执行槽，如实注册 `slots=1`。指定 `--stage-type` 时仅声明对应能力，指定 `--job-id` 时公开目标限制，不能被当作能处理其他任务的通用执行器。

通用 Worker 按阶段类型轮换查询，每类最多查看 4 个候选，一轮最多 5 次查询、20 次领取尝试。某类资源饱和时继续查看其他类型，避免大量媒体任务占据候选列表前部时挡住文本阶段；这不构成优先级或全局公平调度的性能承诺。

本地还使用单调时钟维护保守存活期限，从注册或心跳请求开始计时。每次领取及阶段 guard 检查同时验证该期限；短 TTL 下即使心跳请求挂起，也不能仅凭仍有效的阶段租约发起新模型请求，迟到的心跳响应不复活已经过期的执行器。

## 容量与正确性

领取阶段时在 Java 事务中统一检查与占用容量，重复领取回执不重复计数。阶段完成、失败或租约回收之后，占用随阶段状态释放。观察到 Worker 离线并不证明其计算或供应商调用已经结束。

第一版配置三类阶段资源上限：`MEDIA` 与 `EXPORT_CLIP` 共用 `FFMPEG`，`ASR` 使用 `ASR`，`SEGMENT` 使用 `TEXT`。它们限制同时被领取的阶段数量；同一阶段内的请求次数继续由原模型预算控制。`TIMELINE` 只受执行器槽位限制。

默认执行器心跳间隔 10 秒，服务端超过 35 秒未见心跳则显示离线，可用 `LIVECUT_WORKER_HEARTBEAT_TIMEOUT_SECONDS` 调整。资源默认值与环境变量为 `LIVECUT_FFMPEG_SLOTS=1`、`LIVECUT_ASR_SLOTS=2`、`LIVECUT_TEXT_SLOTS=2`；这些是保守配置，不是机器吞吐量实测值。多个 Java 实例共享数据库时须使用相同容量配置。

生产默认 `LIVECUT_WORKER_REQUIRE_REGISTRATION=true`。旧协议测试上下文显式使用兼容模式隔离验证原有回执，新的执行器集成测试保持强制注册；生产升级需要同时更新 Worker，不能通过自动回退绕过注册与容量检查。

阶段资源限制不等同于供应商侧精确的在途请求数或 QPS 限流。外部请求读超时、Worker 退出或阶段租约失效时，供应商可能仍在计算。`UNKNOWN_OUTCOME` 不被本轮自动重发或退还预算；本轮不宣称供应商侧 exactly-once，也不把调用次数换算为人民币费用。

## 页面协议

独立请求 `GET /api/executors`，选中任务时使用 `?job_id=<UUID>`，避免把只服务其他任务的 Worker 算作可用。

返回服务端 `generated_at`、心跳超时配置、在线执行器与槽位统计、逐阶段可用性和资源占用。执行器列表只含公开 ID、状态、能力、槽位、最后心跳和目标任务，不含会话、`run_token` 或鉴权信息。

逐阶段原因分为：

- `NO_EXECUTOR`：没有在线且能力与目标匹配的执行器。
- `BUSY`：有匹配执行器，但执行槽位已满。
- `RESOURCE_BUSY`：执行器有空位，但该阶段资源达到上限。
- `AVAILABLE`：可以等待下一轮领取。

这些是观察时的快照，实际领取仍在事务中重新检查。接口错误显示“执行器状态暂不可用”，不能当成全部离线，也不影响原有视频、任务和审核加载。已完成任务不因空闲执行器离线变为失败。

## 验证口径

使用独立测试数据库验证注册幂等、会话替换与迟到心跳、两个 Worker 竞争最后一个槽位、全局阶段资源限制、目标及能力过滤、注销与仍有效租约、重启后的状态，以及旧任务回执兼容。合成协议测试不调用付费模型，不用于证明识别质量或生产吞吐量。
