# 带字幕成片导出

目标：已完成字幕校对的用户，直接得到包含字幕像素的可发布 MP4。原 clean MP4、字幕修订、原分析、审核与素材包保持独立。此次使用固定字体/样式/画幅异步渲染，复用 EXPORT / EXPORT_CLIP、FFMPEG 容量、attempt/run_token、租约及媒体子进程取消，不调用模型或 ASR。

## 产品与 API（实现冻结 v1）

字幕弹窗用稳定子页“校对字幕 / 带字幕视频”。保留草稿；有未保存字幕时阻止新建渲染，但仍可看历史。明确选择一个已确认 rN（最新为草稿时仍可选旧确认版）。空字幕不能声称带字幕成片，创建返回 CAPTION_RENDER_EMPTY。预览样式示意不能冒充真实烧录；成功产物提供原生视频预览及原生下载。

- GET/POST `/api/exports/{sourceE}/clips/{sourceC}/caption-renders`。GET 返回 `{items:[RenderSnapshot]}`，按创建时间倒序，最多 50 项。POST 必须 Idempotency-Key，严格 body `{caption_revision,caption_content_hash,style_preset,frame_preset}`。
- GET `/api/caption-renders/{id}`；POST `/{id}/cancel`、`/{id}/retry`；GET/HEAD `/{id}/content`，`?download=true` 下载，支持 Range。
- style_preset 枚举 `WHITE_OUTLINE_V1`（白字黑描边）、`DARK_BOX_V1`（深色底字幕）。原 frame_preset 为 `SOURCE`、`LANDSCAPE_720`（1280×720）、`PORTRAIT_720`（720×1280），使用 contain+补边保留完整画面，SOURCE 仅必要时补至偶数尺寸。扩展 `PORTRAIT_BLUR_720`（720×1280）见[竖屏柔化背景](./50-竖屏柔化背景.md)，前景完整保留、同源画面柔化填充背景；旧三种画幅语义不变。
- profile_version 固定 `caption-burn-v1`，内部 encoding_profile 为 `h264-aac-burn-v1`；H.264/yuv420p，有原音轨才输出 AAC。

RenderSnapshot 为独立平铺 DTO（不修改 clean Export Snapshot）：id 为新的 export UUID；字段 `source_export_id,source_clip_id,job_id,caption_revision,caption_content_hash,source_clip_sha256,style_preset,frame_preset,profile_version,font_profile,status,state_version,attempt,created_at,updated_at,error_code,diagnostic,actions,progress,content_url,download_url,size_bytes,media`。

status 为 QUEUED/RUNNING/SUCCEEDED/FAILED/CANCELLED。actions 为 `{can_cancel,can_retry,max_attempts,retry_block_reason}`，max_attempts 沿用配置；失败且次数未耗尽才可 retry；CANCELLED 不被迟到回调或 retry 复活，可用新的创建键重新生成。retry_block_reason 为 null/NOT_FAILED/ATTEMPTS_EXHAUSTED/CANCELLED_REQUIRES_NEW_RENDER/INPUT_REQUIRES_NEW_RENDER。缺字、字幕过长和量化后空区间三种确定需要修改字幕的错误禁止对原冻结任务重试；修订确认后新建。旧 Export retry 路由也执行同一限制。未成功时 content_url/download_url/size_bytes/media 必须 null；成功 media 为 `{duration_ms,width,height}`。公开 URL 仅此 render 的上述同源 content 路由，不暴露私有 key/路径/会话。

重复同 key 同 body 返回同一渲染（含终态）；同 key 异 body 返回 IDEMPOTENCY_CONFLICT。不同 key 允许重建同一配置，export fingerprint 计入 request key 哈希，避免取消任务永久黏住创建。GET 不持有确认或写入新字幕；完成内容 GET 重新校验已登记成片字节。新 caption_render 关系表记录源和幂等身份；export_job.render_mode 默认 CLEAN，新渲染为 CAPTIONED。旧 export 列表排除派生渲染；CaptionSourceResolver 只接受 CLEAN，禁止把已烧字幕版本再次作为原片初始化。

## 冻结输入与执行协议

创建由独立 CaptionRenderService 编排，避免 ExportService→CaptionService→CaptionSourceResolver→ExportService 循环。使用 readConfirmedForDelivery，内部带出已验证 clean clip key 与媒体信息；字幕已是 clip-relative 时间，不能再按原 parts 重切或再次映射。

claim 的 config.export 保留 base 身份字段，start_ms=0、end_ms=输入实际媒体时长；追加 `render_mode:'CAPTIONED'`、`caption_render_hash` 和 `caption_render`（见 contracts/caption-render-spec.schema.json）。旧 ExportSpec exact-field 分支保持。

caption_render 包含：schema_version=1、profile_version、source_export_id/source_clip_id/source_snapshot_hash；input_media 的 key/sha256/size_bytes/duration_ms/width/height/has_audio；captions 的 revision/content_hash/cues_key/cues_sha256/duration_ms（逻辑时长）；style_preset/frame_preset/output{width,height}；font{profile_id,family,key,sha256,size_bytes}；timing_basis='CLIP_RELATIVE_ASS_CS_FLOOR'。整块 canonical hash 为 caption_render_hash，并进入新的 snapshot_hash、stage_input_hash 与 fingerprint。lease 的原 source key/hash 保持原视频身份语义，渲染分支只读取 nested input_media 已验证成片，不重扫/重切原视频。

cues 文件 canonical JSON：`{schema_version:1,duration_ms:<逻辑时长>,cues:[{id,start_ms,end_ms,text}]}`，SHA 单独绑定。至少 1 条、最多 10000 条；单句至多 2000 UTF-16 单元，文本合计至多 2 MiB，文件至多 8 MiB；半开整数毫秒、按开始排序且不重叠、均在逻辑时长内。logical_duration 与实际 MP4 duration 分开，不拉伸音视频。ASS 两端向下量化为 10ms 网格，量化为空区间明确报 CAPTION_RENDER_TIMING_UNSUPPORTED，不静默丢字；不按字数猜词时间。

固定 Noto Sans CJK SC Regular 2.004，profile_id='noto-sans-cjk-sc-2.004'，family='Noto Sans CJK SC'。官方仓库 commit 523d033d6cb47f4a80c58a35753646f5c3608a78，Sans/OTF/SimplifiedChinese/NotoSansCJKsc-Regular.otf，16437364 bytes，SHA256 2c76254f6fc379fddfce0a7e84fb5385bb135d3e399294f6eeb6680d0365b74b。配置 LIVECUT_CAPTION_FONT_PATH，默认 data/fonts/noto-sans-cjk-sc-2.004/NotoSansCJKsc-Regular.otf。创建时校验固定字节并复制至 storage 中按哈希命名的不可变字体 key；cues 同样采用不可变 key。二进制与第三方字体许可放本地忽略目录，不提交 Windows 字体或为整个项目添加许可证。安装脚本校验哈希并保存上游许可。

Worker 使用程序生成 ASS，纯文本编码参考 FFmpeg ff_ass_bprint_text_event：避免把原花括号/反斜杠/HTML作为标签或控制序列。filter 仅程序常量，在本 attempt 子目录以固定相对名 captions.ass 与 fonts 执行，不拼接用户 filter，不全局 os.chdir。字体、cues、输入 MP4 哈希及边界均先核验；输出探测 H.264/音轨/尺寸/时长并完整解码；guard 在渲染、解码与最终原子发布前生效。字体和显示区域必须支持实际文本，不得截断原文或把缺字悄悄当作成功。

v1 首次发布前的真实课程验收补齐排版适配：默认字号为画面短边的 4.5%（至少 12px），在默认字号至其 80% 的可读下限内，有限搜索能够容纳全片字幕的最大整数字号，整片使用同一字号。按真实字体 advance 计算行宽，字幕最多六行且不超过画面高度的 32%；下限仍不够时明确报错。英文优先在空白边界换行，保留原字符和空白；中文及无空白长串允许逐字换行，显式换行和空行保留。此调整不重新识别、改写或截断字幕，也不猜测句内时间。原视频已经写入画面的字幕会与新增字幕一并保留，页面在生成前说明。

manifest 新分支 data_kind='captioned_export'，保留完整 stage/export/base 身份，额外 render_mode='CAPTIONED' 与 caption_render_hash，绑定 profile/字幕源/输入/font/几何；旧 reviewed_export 不能冒充烧录结果。可增加小型 caption_render_info 产物核验冻结来源，不把 2MiB cues echo 进 manifest。checkpoint 同样绑定全部冻结输入，重复 attempt 仅复用自己已验证的原子输出。

## 进度、取消与恢复

新增 stage 私有 `render-progress` 回调，沿用原凭据；payload 附 sequence（递增整数）、phase（PREPARING/ENCODING/VALIDATING/PUBLISHING）、processed_ms、total_ms。仅 CAPTIONED/EXPORT_CLIP 接受；total_ms 必须匹配输入实际时长，0<=processed<=total。Java 在当前 attempt/token 和 active owner 内更新，重复/迟到 sequence 不回退，阶段顺序不回退；同 attempt 崩溃重入需持久化并合并已报告的 sequence/phase/processed 高水位，不能重新报告 PREPARING 0；触发父级 state_version 更新。公开 progress 为 null 或 `{phase,processed_ms,total_ms,updated_at}`。FFmpeg 使用真实 out_time_us/1000 并限频回报；ENCODING 的 100% 不等于成功，只有完成全部验证和发布才开放下载。短暂进度上传失败不能伪造进度；租约 fencing 立即停止媒体进程。

取消只锁 analysis→当前 derived export→其 stages，清本 owner 的活动 token/worker/session/lease/deadline并保持 CANCELLED。refreshLocked 必须保护 CANCELLED，不能把全取消归为成功。原分析、原导出、字幕确认不变；其他 render 不受影响。FAILED 重试沿用原冻结内容与 max_attempts，取消后新建使用新键。存在未完成文件时不公开下载。

主要错误：CAPTION_RENDER_INVALID_INPUT(400)、CAPTION_RENDER_EMPTY(400)、CAPTION_RENDER_REQUIRES_CONFIRMATION(409)、CAPTION_RENDER_REVISION_MISMATCH(409)、CAPTION_RENDER_SOURCE_UNAVAILABLE(409)、CAPTION_RENDER_FONT_UNAVAILABLE(503)、CAPTION_RENDER_NOT_FOUND(404)、CAPTION_RENDER_NOT_CANCELLABLE(409)、CAPTION_RENDER_NOT_RETRYABLE(409)、ATTEMPTS_EXHAUSTED(409)、IDEMPOTENCY_CONFLICT(409)。Worker 保留受控输入/字体/媒体/解码/时序错误，不输出假成片。

创建请求的未知结果按完整四字段配置分别保存回执。A 配置超时后切换 B，再回 A 或刷新页面，仍复用 A 原键；B 成功仅清理 B 的匹配回执。兼容旧单项回执时也必须配置完全匹配，不覆盖其他配置的未决请求。不按时间或容量静默淘汰未知结果；浏览器无法持久保存新请求时，在 POST 前提示，避免刷新后失去请求身份。记录中的耗时标为“距创建”，不把重试前的历史时间称为本次排队耗时。

## 验收要求

1. Java 合成/真实数据库：严格确认/旧版本/空字幕/哈希/幂等，独立列表，排队取消/运行取消/迟到回调 fencing，FAILED 有限重试、CANCELLED 不复活，原数据不变。
2. Python 真实 FFmpeg：中文、换行、花括号、HTML与字面反斜杠序列；有/无音轨、三画幅两样式、真实时段出现/消失帧及多区间输入不重切；完整解码/时长/尺寸、源或字体或cues篡改拒绝、取消丢租回收、同 attempt 恢复绑定。
3. 浏览器：两字幕子页/草稿/待提交保护，冻结旧确认版、配置明确、真实进度、取消/重试/成功预览和原生下载；320px/中等/桌面无溢出，原 clean 下载/字幕/素材包仍可用。
4. 本机至少真实课程与多区间两类成片；抽帧视觉核对字幕、特殊字符和空白区，文件完整解码及下载大小/SHA256。原 11 项业务资源基线一致、模型请求 0。

## 本机验收记录（2026-11-07）

已部署本机 Java/V16 和 Worker，使用既有真实课程及 KV Cache 多区间成片验证。没有重新提交 ASR 或文本分析。验收产物、原素材、字体、数据库备份、截图和带私有身份的执行文件均留在忽略目录，不提交公开仓库。

- 三种画幅与两种样式均有真实输出；课程保留原画幅、KV 多区间原画幅/横屏/竖屏通过下载大小、SHA256、HEAD、Range、音轨、时长和完整解码核对。多区间输入直接使用已完成的 clean MP4，不重新按源 parts 切片。
- 课程旧确认字幕 r0 经浏览器创建竖屏成片；真实长句为 264 字符，整片统一 27px，19 条归一化原文全部保留，最多六行。实际抽帧核对换行和字幕可见性。早期竖屏长句报错记录保留，排版适配后使用独立任务验证，不把原失败改成成功。
- 运行取消已观察到实际 FFmpeg 子进程退出、迟到 heartbeat 被拒绝；单槽编码占用时另一任务排队，取消后后续任务正常执行。手机页面另外从真实编码 4% 使用“取消生成”，该记录持续为 CANCELLED，没有下载和重试入口。手机创建后自动滚到新记录也已实际验证；另一条较快完成的手机原画幅样本保留为 SUCCEEDED，不作为取消成功证据。
- 真实失败恢复使用独立故障演练：只在新派生任务 attempt1 自身已验证的编码临时文件出现后，创建同目录的 `clip.mp4` 空目录，模拟最终文件发布失败。实际结果为 `FAILED / OUTPUT_WRITE_FAILED`，内容接口 409，页面显示恢复说明与重试按钮。没有停止 Worker、改共享输入或伪造模型/编码响应。
- 从浏览器点击该失败记录的“重试此任务”，同一个 render/stage/snapshot 在 attempt2 成功；当时表单选择横屏，任务仍使用原先冻结的 r0/深色底/竖屏配置。重试开始后关闭字幕窗口，后台正常完成，再打开可预览与原生下载。成片为 720×1280、H.264/AAC、128584ms、5570913 字节，下载哈希与清单、ETag 一致，完整解码通过。旧 attempt1 heartbeat 实际返回 `409 STALE_ATTEMPT`，成功快照前后完全一致。
- 浏览器验证了字幕草稿禁新建、历史确认版选择、保留历史下载、预览关闭/放大/恢复焦点、隐藏暂停、桌面及 320px 无横向溢出。IAB 不支持原生全屏时，实际验证的是窗口内放大回退，不宣称其原生全屏通过。
