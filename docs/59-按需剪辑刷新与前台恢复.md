# 按需剪辑刷新与前台恢复

长视频的完整转写会随剪辑请求快照返回。旧工作台用 v-show 保留编辑器，剪辑区隐藏后仍每 5 秒请求历史列表、选中详情和导出；历史项又各自带完整 ASR，重复传输与校验随历史数和原句数增长。本轮先调整刷新生命周期，减少用户没有查看时的重复读取，保留草稿和执行状态恢复。

## 调度行为

- 只有剪辑工作区 active 且页面可见时自动刷新；切换工作区、隐藏页面或卸载时停止计时，并取消/隔离本轮只读 GET。
- 可见时，有 QUEUED/RUNNING 查找或尚未完成的成片任务，保持 5 秒核对；已知全部终态后改为 60 秒，仍能发现其他页面新增的请求和成片。
- 返回工作区、恢复页面可见、窗口重新获得焦点以及写操作结束时，立即重新只读核对；显式“刷新”继续可用。
- 写操作期间不启动竞争性的自动读取。暂停的是只读刷新，不取消已经提交的写请求，也不丢弃原幂等键、预算、UNKNOWN/保存待核对信息。

全局请求数或跨标签页 exactly-once 不由本调度器保证。窗口 focus 等事件可合并到同一次刷新；同一时刻只保留一个刷新任务，正在执行时不并发开启另一轮。隐藏/重入后的旧任务即使迟到，也不能发布到新生命周期；旧回调结束不能清掉新任务的 loading 或计时状态。

## 编辑与来源约束

调度器不重挂载编辑器，不保存、确认、导出或发模型请求。来源、revision/hash、草稿冲突和回执核对仍由原解析与采纳逻辑负责。隐藏时保留原输入、所选原句、方案修改及本机备份；返回后先读取新快照，不能把本地修改当作服务端版本覆盖。

计时器使用可控时钟并与只读 AbortSignal 关联；选择变化仍使用原 IntentReadScope，生命周期过期和选择过期任一成立都不能采纳响应。模型后台执行由 Java/Worker 管理，页面暂停刷新不表示任务已取消，也不停止服务端处理。

本轮范围是 IntentClipPanel 的列表、选中请求详情和其导出读取。字幕、AI 字幕建议、话题与对话各自的刷新生命周期另行核对，不以本轮调整宣称整个页面隐藏后所有网络请求为零。

## 验证口径

使用可控时钟覆盖隐藏/恢复、运行/终态间隔、窗口聚焦、在途读取消、迟到回调、重入、写操作阻塞和卸载，验证实际发起次数与可发布权限，不只检查一个 interval 常量。

浏览器使用两个只读 QA 入口：一份冻结的旧构建与当前源码，代理同一隔离 Java 来源，服务端计数列表/详情/导出 GET 并拒绝所有业务写。比较相同隐藏工作区场景下的实际请求；进入剪辑区及手动刷新必须能取得同一份已保存方案。结果只证明刷新策略，不换算长视频时延、吞吐量或费用下降。

列表本身仍可能携带多份全量转写，本轮没有修改其分页/摘要契约。因此可见时的单次大响应开销仍存在，后续应单独验证轻量历史列表及按选中加载详情，不能把后台暂停当作这部分已解决。
