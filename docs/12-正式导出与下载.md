# 正式导出与下载

后续增加导出批次文件清单 JSON 附件下载，见 [留档下载协议与验收](./15-确认结果与文件清单下载.md)。

T6 将已确认的审核修订转为独立 MP4。导出由 Java 创建并冻结输入，Python 单槽 Worker 计算。每个片段使用现有 job_stage 表和领取、心跳、attempt/run_token、完成回调及租约回收协议，没有另存一份权威执行状态。

## 页面操作

沿用 README 的 Java、Worker 和 Vue 启动方式。在审核区保存并确认一个版本，点击“跳到正式导出”。

1. 选择当前或历史已确认版本。未保存修改和其他草稿不参与这个导出。
2. 选择商品；切换商品时默认选中该商品的全部已启用讲解片段，也可取消部分片段。
3. 点击“创建 / 打开导出”。相同冻结输入返回同一个批次，重复点击不会重复建立计算任务。
4. 每段独立显示状态，成功后可预览和下载 MP4。单片段失败可独立重试，不会重新转码已成功片段。

当前固定编码配置 h264-aac-v1：H.264/libx264、veryfast、CRF 23、yuv420p、AAC（有源音轨时）、faststart。不使用 stream copy，不进行跨时段混剪、字幕烧录或自由 FFmpeg 参数执行。实际切点仍受源帧和音频编码约束，不能宣称任意毫秒都对应独立视频帧。

## API

```http
POST /api/exports
Content-Type: application/json
```

```json
{
  "job_id": "分析任务UUID",
  "approved_revision": 2,
  "segment_ids": ["segment-0001", "segment-0009"],
  "profile": "h264-aac-v1"
}
```

输入只引用已确认修订中的启用片段，商品归属必须明确。segment_ids 需要 1～100 个唯一 ID，重复 ID 返回 400；选择顺序不影响批次身份。可导出历史已确认修订，即使最新版本已经变成新草稿。服务端从该修订读取名称与毫秒边界，不接受客户端另传时间或路径。

| 请求 | 行为 |
|---|---|
| `GET /api/exports?job_id={id}&limit=20&offset=0` | 分析任务的导出批次，limit 上限 100 |
| `GET /api/exports/{id}` | 批次与逐片段状态 |
| `POST /api/exports/{id}/clips/{clip_id}/retry` | 仅重试该失败片段，仍受 attempt 上限约束 |
| `GET /api/exports/{id}/clips/{clip_id}/content` | 成功成片预览，支持 Range |
| `HEAD /api/exports/{id}/clips/{clip_id}/content` | 返回成片长度与媒体头 |
| `GET /api/exports/{id}/clips/{clip_id}/content?download=true` | 以安全生成的文件名下载 |

批次响应包含 id、job_id、video_id、approved_revision、snapshot_hash、profile、status、state_version 和 clips。每片段包含 id、segment_id、product_id/name、固定 start_ms/end_ms、stage_id、status、attempt、error_code、size_bytes；content_url/download_url 仅在成功后可用。不暴露 run_token、磁盘路径、manifest key 或 Provider 原始响应。

批次状态为 QUEUED、RUNNING、SUCCEEDED、PARTIAL_FAILED 或 FAILED。部分片段成功、其他片段失败时保留成功成片并显示 PARTIAL_FAILED；单项重试后重新聚合状态。没有完成的批次不显示“全部导出成功”。

## 冻结和隔离

创建导出时冻结分析上下文、视频来源哈希、已确认修订、片段 ID、商品名、区间与编码版本。指纹按规范化输入计算；选择数组顺序不改变同一批次身份。后续编辑、确认新版本或商品改名不改变既有任务。

每片段创建 owner_type=EXPORT、owner_id=export_job.id、stage_type=EXPORT_CLIP 的 job_stage。job_id 保留分析上下文。分析阶段的状态、依赖推进、失败传播和公开阶段列表只处理 ANALYSIS owner；导出失败不能把 REVIEW_READY 分析改成 FAILED，也不能阻止无关片段完成。

内部 claim 的 config.export 包含 export_id、clip_id、approved_revision、snapshot_hash、segment_id、start_ms、end_ms 和 encoding_profile。Worker 验证固定配置、源文件哈希与真实时长，再在当前 attempt 内输出 clip.mp4 和 media-info.json。manifest 标记 reviewed_export / CONFIRMED，并绑定 stage_input_hash 和冻结字段；正式成片不作为模型原始预测或自动质量标签。

Java 完成接口核验 manifest、身份和文件哈希，再引用不可变成片。GET/HEAD 内容接口也验证成片引用和哈希。失败项重试会生成新 attempt 目录，旧 attempt 不能覆盖新结果。Worker 同一 attempt 的已发布文件可在验证输入与 checkpoint 后恢复；完成响应丢失只重放完成回调。

EXPORT_CLIP 不访问模型，预算传输层拒绝其 HTTP 调用；本功能不新增模型请求和账单。FFmpeg 与完整解码检查都有超时，计算并发继续由单槽 Worker 限制。
