# 按原句人工剪辑

用户已知道想保留哪几句话时，应能明确选择起止原句后直接剪辑，无需先请求AI生成候选。现有“人工选用”只承接已有AI方案中的待核对候选，不能从零建立本流程；现有话题草稿也不作为独立人工片段的存放位置。

## 用户流程

在“原句搜索”的“搜索与回看”视图中选择原句，明确点击“设为人工起句”或“设为人工止句”。范围草稿独立于当前选句和查询，可以跨页、跨搜索词选择，但只能属于同一完整转写来源；搜索、翻页、同任务切页不清范围。起止不能倒置，不静默交换。首版每个人工方案对应一个连续区间和一个成片，保留起句开头至止句结尾之间的全部音画、原句和静音，不只拼接搜索命中项。

“人工剪辑”是原句搜索内的第二个视图，不添加第六个主工作区。独立展示起止句、标题、全局时间、句数和预计时长，可明确预览完整选定区间。预览不保存、不确认、不导出；播放器与搜索页独立，隐藏、切源、修改范围或手动操作时取消旧播放意图，旧元素事件、metadata和play承诺不能作用于新意图。

用户明确创建人工方案，得到真实人工r1；修改保存为r2等新修订。再明确接受句级边界并确认该版本，才可以生成MP4。新修订不继承旧确认，旧确认和已导出文件保持不变。修改旧版本不能覆盖当前head，先读取当前版本并核对。历史只读元数据与完整详情分开，摘要不能用于确认、保存或导出。

手动流程不建模型规划stage、模型预算、账本或假model_result/FOUND，不使用空文本模型或dummy clip_request_id来套旧协议。语音时间为原视频全局毫秒；人工选择不等于独立语义完整性或ASR准确率评测。

## 数据与来源

新增独立人工plan、不可变revision和confirmation存储。plan固定所属job/video/generation及source；公共source沿用转写接口8字段。内容包括title、start_utterance_id、end_utterance_id及服务端推导的range：start_ms/end_ms/utterance_count/start_text/end_text。只接受真实起止ID，不信任客户端时间、句数或原文；按完整ASR顺序解析全部中间原句。

source_fingerprint必须与创建时真实核验的ASR和时间轴一致。新增创建、修订、确认及首次导出的人工来源文件IO先在业务事务和行锁之外完成，再在持有所属分析/人工plan等正确锁顺序后核对该次已验证的来源元数据，变化则拒绝，不能在业务已经提交后才做会导致错误回执的外层核验。保留旧转写GET的只读、无行锁语义。既有Export/Caption读取、领取、完成和交付消费中的媒体/ASR核验继续遵循原事务与锁顺序，本轮不宣称全链路文件IO均已迁出锁。所有消费端重新核对已存内容的canonical hash、真实来源和授权，不仅依赖可变head或数据库一列hash。

## API与回执

人工端点均独立于旧AI端点。首次修订为1，revision使用非负安全整数的合法正范围；旧AI和话题r0语义保持。

创建前可显式GET `/api/jobs/{jobId}/transcript/range?source_fingerprint=...&start_utterance_id=...&end_utterance_id=...`核对完整范围。响应为`schema_version=1.0,data_kind=transcript_range,source,start_utterance_id,end_utterance_id,range`，复用原严格只读来源管线；range为下述5字段。参数缺失/重复/未知或指纹语法错误沿用INVALID_TRANSCRIPT_QUERY，来源沿用TRANSCRIPT_*，非法/未知/倒序原句为400 MANUAL_CLIP_INVALID_RANGE。获得当前精确范围前，不从搜索命中数量推测完整区间句数。

- POST `/api/jobs/{jobId}/manual-clip-plans`，Idempotency-Key必填，body精确为`{source_fingerprint,title,start_utterance_id,end_utterance_id}`。title保留请求原文，非空白且最多120个UTF-16单元。起止ID符合已有ASR ID规则，必须同源、有序。
- POST `/api/manual-clip-plans/{id}/revisions`，独立Idempotency-Key，body精确为`{base_revision,base_plan_hash,source_fingerprint,title,start_utterance_id,end_utterance_id}`。必须基于当前head的确切版本/hash，成功建立base+1，不覆盖旧内容。
- 两种写返回immutable提交回执：`schema_version=1.0,data_kind=manual_clip_submission,operation=CREATE|REVISION,job_id,plan_id,idempotency_key,input,request_hash,revision,plan_hash`。input保留该次精确请求；request_hash绑定版本化operation/所属job或plan及canonical input。相同key和不同input/归属冲突；重复请求和回执GET始终指向原写入修订，不能用已编辑的新head冒充原创建结果。回执不作为确认或导出凭据。
- GET `/api/jobs/{jobId}/manual-clip-plan-submissions/{key}` 与 GET `/api/manual-clip-plans/{id}/revision-submissions/{key}`精确读取上述回执。只有对应业务提交确切不存在的404才可原key/body重试；网络、500、协议失败或未知结果均不自动换key重发。回执可在当前产物不可用时找回既有写入，但必须验证存储的原指纹和原修订身份。
- GET `/api/jobs/{jobId}/manual-clip-plans?limit=20&offset=0`为只读元数据分页（limit1～50、offset非负安全整数）：`schema_version=1.0,data_kind=manual_clip_plan_list,job_id,items,total,limit,offset`；item精确为`id,job_id,video_id,title,revision,plan_hash,status,created_at,updated_at`，status仅DRAFT/CONFIRMED，不返回全文转写。总数/页为单次读取结果，不承诺跨请求成员快照。
- GET `/api/manual-clip-plans/{id}`，可带revision读取旧修订；详情为`schema_version=1.0,data_kind=manual_clip_plan,source_kind=MANUAL_ASR,id,source,revision,latest_revision,plan_hash,status,confirmed_revisions,created_at,updated_at,title,start_utterance_id,end_utterance_id,range`。range为`start_ms,end_ms,utterance_count,start_text,end_text`，不返回完整转写。plan_hash绑定版本化身份、source、revision及全部内容，时间/文案不从摘要拼造。详情须真实来源核验。
- POST `/api/manual-clip-plans/{id}/confirm`，body`{revision,plan_hash,accept_sentence_boundaries:true}`，只确认当前确切版本，保存原确认记录并返回完整manual详情；显式确认不触发导出。
- POST `/api/manual-clip-plans/{id}/exports`，Idempotency-Key必填，body`{revision,plan_hash,profile:'h264-aac-v1'}`；只导出该已确认版本，返回标准ExportSnapshot。GET同路径读取该人工方案的导出，采用既有Page`{items,limit,offset}`，默认limit20/offset0并校验有界分页参数。
- GET `/api/manual-clip-plans/{id}/export-submissions/{key}`精确读取原导出批次的当前有效Snapshot；只有404 MANUAL_CLIP_EXPORT_SUBMISSION_NOT_FOUND才允许用户用原key/body重试创建导出，其他故障保留未知状态，不能自动换key追加编码。

Idempotency-Key沿用安全格式`[A-Za-z0-9_-]{1,100}`，客户端使用UUID；CREATE与REVISION共享单一key空间，同key不同operation、归属或input均冲突。request_hash是UTF-8字符串`manual-clip-request-v1\n{CREATE或REVISION}\n{CREATE的job_id或REVISION的plan_id}\n{canonical(input)}\n`的SHA256，含末尾LF。canonical递归按UTF-16字典序排序key，整数和JSON字符串原文序列化，不trim或NFKC，不额外转义中文。

plan_hash是对象`{schema_version:'1.0',data_kind:'manual_clip_plan_revision',source_kind:'MANUAL_ASR',id,source,revision,title,start_utterance_id,end_utterance_id,range}`的canonical JSON SHA256，排除head、status、时间和确认；确认不改变内容hash。客户端核回执和详情的实际hash绑定，不只检查64位格式。

共同结构见[人工方案](../contracts/manual-clip-plan.schema.json)、[元数据列表](../contracts/manual-clip-plan-list.schema.json)、[提交回执](../contracts/manual-clip-submission.schema.json)与[原句范围](../contracts/transcript-range.schema.json)。Schema约束结构，实际source、时序、UTF-16预算、当前修订和hash绑定另由程序验证；合成夹具不作为真实模型或成片结果。

错误码独立以MANUAL_CLIP_命名：参数400 MANUAL_CLIP_INVALID；缺失plan/revision/提交404 MANUAL_CLIP_NOT_FOUND/MANUAL_CLIP_REVISION_NOT_FOUND/MANUAL_CLIP_SUBMISSION_NOT_FOUND；无合法原句范围400 MANUAL_CLIP_INVALID_RANGE；来源不符/不可用409 MANUAL_CLIP_SOURCE_CHANGED/MANUAL_CLIP_SOURCE_INVALID；旧base或hash冲突409 MANUAL_CLIP_REVISION_CONFLICT；未确认409 MANUAL_CLIP_CONFIRMATION_REQUIRED；回执破损409 MANUAL_CLIP_SUBMISSION_INVALID；重复key冲突沿用409 IDEMPOTENCY_CONFLICT。空、重复、未知查询参数按新接口拒绝。模型、Worker和旧AI接口不新增手动规划入口。

## 导出、字幕与交付兼容

export_job增加独立可空manual_clip_plan_id，与clip_request_id互斥。人工CLEAN导出冻结manual plan ID、确认修订/hash、完整source和起止ID/实际区间，snapshot/claim/完成/内容/重试/manifest/ZIP均消费同一人工证明；不查假review_document，不把人工plan ID冒充clip_request。原话题导出列表排除人工来源，旧指纹/字段集保持。

单区间编码复用原EXPORT_CLIP的base8 claim字段，不给Worker增加parts/duration/clip_request_id或CLEAN标记，不改旧输入/能力语义。真正FFmpeg输出仍有真实stage、attempt/run_token、媒体校验和产物manifest；无规划stage不等于无导出stage。今后需要多段拼接时须独立设计新输入与能力隔离，本轮不伪装成已有parts分支。

字幕、字幕ZIP、纯MP4 ZIP及带字幕派生导出都识别并复核人工来源；烧录消费时重核原人工确认与来源，不因当前head已修改而否定正确旧确认，也不继承新确认。公开export snapshot/manifest及MP4 ZIP只在人工来源时增加manual_clip_plan_id，旧非人工字段形状和指纹不变；前端下载选择身份包含该关联，不能跨来源复用准备链接。

## 前端保护与验收

独立ManualClipPanel拥有范围/标题草稿、历史、提交回执、当前版本及播放器，父搜索页仅显式传递当前已核对的选句，不把可变selected当永久范围。dirty/pending/未知提交纳入Workbench的任务切换、上传和unload保护。旧AI输入、原提交、方案与字幕草稿不覆盖。隐藏不取消已发出的业务写，但停止只读轮询与播放；旧读/finally不能清新生命周期。

创建与修订提交前先在独立本机槽保存原key/body/归属，写成功才发送；本机保存失败则不提交。未知结果禁新key重试，先精确查询原回执；回执与原input核对后读取该不可变revision，head已推进须明确核对，不能以最新详情认领原提交。成功后仅清理自己的相同记录，不删除其他窗口/历史回执；普通未保存范围仅承诺同任务页面保留，不声称刷新后已备份。

当前首次提交的明确未写入拒绝（400 MANUAL_CLIP_INVALID/INVALID_RANGE，409 MANUAL_CLIP_SOURCE_CHANGED/SOURCE_INVALID/REVISION_CONFLICT/CONFIRMATION_REQUIRED）可清自己的相同entry并保留draft供修正；服务端保证这些拒绝原子回滚，没有新增plan/revision/receipt。IDEMPOTENCY_CONFLICT/SUBMISSION_INVALID、网络/500/协议失败、已未知或恢复的旧entry均不走此清理。业务写在隐藏时完成只处理原回执，不触发隐藏的完整详情读取或覆盖新草稿。

验证需覆盖：真实MySQL创建/修订/冲突/回执/确认/导出，假ID/倒序/跨源与篡改拒绝；source文件IO/锁顺序、未选中间句不被跳过、原话题/AI/字幕/ZIP回归。前端跨页范围、脏稿/未知回执、失败重试、来源和播放器迟到隔离、320px可用。真实闭环在新隔离克隆库进行，只用既有ASR，实际生成MP4并核ffprobe/字节与来源；原来源库和原素材摘要保持。没有实际成片前不得报告真实端到端导出已通过。

## 实现与真实验收（2026-11-11）

已实现上述独立人工方案、修订、确认、提交回执、完整范围读取及成片交付。当前目标按用户最新说明收敛为秋招面试：人工剪辑展示人工兜底和工程可靠性，不能当作模型创新或商业需求已验证。AI 差异化应继续围绕现有 Agent 的证据补充、画面观察和可重复对照评测展开。

真实验收使用既有90分钟视频的756条ASR，起止为01:34.046至02:21.255：4个连续原句、逻辑时长47.209秒，其中一条中间句不命中搜索词。生产构建中的跨文字/时间查询选句、完整回看、保存、确认和导出均实际执行；未只拼接命中项，也没有新增ASR或模型请求。

- 真实MySQL/API前置检查16次请求均通过，覆盖范围与来源、非法写入、严格参数、精确回执不存在和空历史。
- 浏览器创建阶段10项通过，其中2项是明确标注的可见性/元数据与HTTP503夹具，其余连接真实API和媒体。CREATE已真正提交后丢弃响应，页面按原key/body读取原回执并恢复r1，无第二次CREATE POST。
- r1已排队时保存未确认r2；r2不能导出，r1仍按原hash和时间区间编码。回执重放不认领新head。后续浏览器复核8项通过，包含精确读取旧r1、实际媒体、已确认字幕、原生ZIP下载与320px操作；模拟的浏览器故障不计为真实供应商故障。
- 第一份真实普通MP4为H.264/AAC、3,935,356字节，ffprobe为47.233秒。单片字幕4条准确对应原句和相对时间，字幕素材包内MP4与原成片逐字节一致；另一个纯MP4 ZIP核对manifest、旧修订、所选文件大小与SHA256。逻辑时长与封装/编码后的实际时长分别保存，不以帧精度冒充毫秒精度。

验收还发现并修复两个真实兼容问题：非帧对齐seek可使普通成片的视频首PTS晚一帧，导致后续严格零时轴的烧录拒绝；Windows较长的attempt目录也可能超过编码进程的工作目录限制。新单段成片使用setpts/asetpts显式归零，发布前继续严格核验；原始视频和烧录输入的零时轴约束未放宽。Windows长目录时仅将已生成ASS和固定字体有界复制到storage内的随机短执行目录，异常、取消和完成均清理，成片和冻结产物仍属于原attempt；根目录本身过长时明确拒绝，不依赖系统8.3短路径。

旧成片、字幕冻结和摘要未被原地替换，原时轴失败记录保留。另建独立人工方案生成零时轴普通片3,936,477字节；其带字幕阶段首次因长目录失败，修复后通过原任务显式retry，attempt2成功，真实MP4为3,875,792字节。两份媒体均为H.264/AAC，format/video/audio起点均为0，实际封装时长约47.234秒（ffprobe小数换算与程序取整可能相差1ms），来源仍为4句47.209秒逻辑范围。下载字节与公开manifest的大小/SHA256一致；实际提取同一5秒位置的原片及烧录帧并查看，确认新增字幕字形和内容真实可见。未新增ASR或模型调用。

Java完整验证488项、前端557项与构建通过。Python定向127项通过，全量1827项通过、102个subtest通过；本机Windows有1个原有POSIX终止信号用例按平台跳过，新增媒体与短目录测试均执行。真实媒体回归包括有声/静音的非帧边界剪辑、再次提音频和烧录、输入非零时轴拒绝、不覆盖旧文件，以及短执行目录的成功/异常/取消清理。真实业务Worker已分别完成普通导出和带字幕派生阶段，本地滤镜试验未替代这些业务验收。

数据保护核验：原保护库27表981行计数与全表hash均未变；隔离克隆库267条模型账本和166个原stage逐行未变，原116个ANALYSIS和29个ASR未新增或重跑。254项、496,562,681字节原文件及隔离副本逐项核对大小与SHA256通过。新增写入仅限隔离库的人工方案、导出、字幕与Worker业务记录。
