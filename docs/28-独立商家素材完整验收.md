# 独立商家素材完整流程验收

2026-10-27。在 `8c7469e` 基线上，用另一商家的 30 分钟录像完成分片上传、真实分析、开发审核和三段正式导出。本轮没有修改生产识别算法，也没有独立人工金标准；结论限于新来源的流程和证据完整性。

## 来源与时间基准

来源为 [臭味滾 ODOUT 商家公开回放](https://livebuy.tv/replays/VHfqqM)，与此前康是美回放的商家、回放 ID 和媒体资产不同；未进行整片内容去重。取开头约 30 分钟作为新的开发输入，不再将它视为封存测试集。模型不接收网页商品跳转点、商品清单或人工区间。

下载过程留有两次失败记录：代理环境下的 FFmpeg TLS 失败，以及直接下载编码超过本地截止时间。未完成的 MP4 单独保留，没有用作分析输入。随后完整下载 180 个 HLS 分片，逐片保存大小与 SHA256；新进程在阻断网络时验证 180/180 分片复用，未发出网络请求。加密、时间轴不连续、不同来源或资产、非 HTTPS 和路径穿越清单在本地获取脚本中被拒绝。这是开发素材获取校验，不是产品上传接口新增的 HLS 功能。

完整编码候选的音频起点为 0、视频起点为 600 ms，被现有媒体探测规则拒绝。保留该候选后，显式补入前 600 ms 的 18 帧黑画面，使容器、音频和视频均从 0 开始。对完整候选的全部 53,982 个真实视频帧，归一化前后 PTS 一致；84,376 个 AAC 包的 PTS、时长和负载摘要一致。此检查只证明相对该完整候选的保留关系，不证明原始 HLS 同步已获得人工核验。

实际输入是这个**显式归一化的开发副本**，时长 `1,800,000 ms`、大小 `111,278,945` 字节，SHA256：

```text
9753505deb6d8d18e20ee651a17b454946b0e14de5bc9480c3300bcd096b5aff
```

输入为 360×640、30 fps、H.264/AAC；完整音视频严格解码与项目 `probe` 均通过。原片时间偏移为 0，但最初 600 ms 是补入黑画面，不能称为未经处理的原片。

## 开发审核与正式成片

预测前固定观察 02:30、07:30、12:30、17:30、22:30、27:30 六个时点，记录画面可见内容；只做 Agent 辅助画面观察，没有听完整音频，且观察者此前看过公开页面的粗略商品信息。观察记录未送入模型，因此不构成独立人工标注。

预测后，开发 Agent 阅读三个候选区间的 ASR，并分别检查中点画面，选出洗碗演示、口腔护理讲解、猫砂演示。r0 原始结果保留；r1 仍有 108 个区间，只启用其中 3 个、关闭其余 105 个，没有修改商品身份和自动时间边界。开发 Agent 的确认只用于流程验收，不代表用户逐段人工审核或全场质量通过。

初次导出核验脚本沿用旧素材的 `yuv420p` 限制，误拒绝本素材实际的 `yuvj420p / color_range=pc`。保留失败记录后，核验接受八位 4:2:0 的相应格式，并要求来源的实际 full-range 标记保留；下载文件、生产编码实现和其他校验没有改变。FFmpeg 对此格式的定义见 [官方像素格式源码](https://github.com/FFmpeg/FFmpeg/blob/master/libavutil/pixfmt.h)。这次修正属于核验条件，不是新编码能力。

审核、导出与后续核验期间，调用账本仍为 TEXT 20、ASR 1，没有新增模型请求。既有 37 个公共业务资源及 782 个文件与本轮前快照的字节/摘要一致。本轮没有对新任务重启 Java，不能将此前任务的重启验收替代本轮记录。

## 发现的问题与下一步

新素材说明固定流程能处理另一商家的输入，也暴露出当前跨窗口按精确名称注册商品的限制：“宠物用洗碗精 / 洗碗精 / 洗碗清洁剂”等分别形成条目，口腔喷雾也有多个相近名称。`洗碗巾` 还需结合原音核实是否涉及 ASR 同音误写；不能仅靠名称就宣判整类错误。17:30 附近存在聊天与商品宣传交织的待复核过渡。

下一轮优先改进有证据约束的商品归并：保持每窗独立发现，再显式引用并校验已有类别身份，保留原提议与别名，区分类别聚合和具体款式，避免商品关键词硬编码及旧类别对新内容的锚定。暂未实现，也没有证明归并质量提升。

仍需人工独立标注后才能报告 Precision/Recall/F1、Temporal IoU、边界误差和返场归并正确率。现有离线评测工具已可用，本轮只生成未评分的证据审计。
