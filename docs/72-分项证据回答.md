# 分项证据回答

2026-11-11。当前Agent已有自主检索与画面工具，本轮补齐回答分项与证据模态/时序绑定。目的是让用户区分原句、画面、前后样本、推断和证据缺口；来源校验不等于语义蕴含校验，不宣称模型准确率提升。

## 用户与执行流程

用户在“结合画面”模式下可明确启用“分项证据回答”。这不是独立收费审核调用，不增加原请求上限；同一视觉模型继续执行原有有界工具循环。模型应为所需事实补查原句/实际画面，证据不足时列出缺口。程序只发布通过分项校验的回答，正文由程序组装，不接受另一段可绕过分项的模型自由正文。原句剪辑仍沿用现有明确选择、核对、保存和确认流程，不从截图或推断自动创建剪辑。

旧普通文本1.0、画面1.1、附加位置1.2的指纹、prompt、预算计划、缓存与已成功结果保留。新增显式字段和独立执行能力，不把新请求交给旧Worker。

## 冻结协议

- POST turns新增可选 `evidence_mode:"structured"`，仅 `visual_mode:"frames"` 允许；省略或明确 `"none"` 沿用旧行为，null/布尔/未知值拒绝。focus仍可选，0有效；普通文本不能开启。新Turn仅在structured时输出 `evidence_mode:"structured"`，旧Turn不补字段。
- V23为agent_turn增加 `evidence_mode VARCHAR(16) NOT NULL DEFAULT 'none'`，约束none/structured。旧turnFingerprint之后、既有focus追加之后，仅新模式追加 `\nevidence_mode=structured`。同key始终优先核对原身份，不能因配置或head变化换请求。
- 新阶段 `AGENT_EVIDENCE`，owner仍AGENT_TURN；保守占TEXT+FFMPEG槽，独立能力注册，仅配置视觉服务的新Worker可广告。无论是否有focus，新模式均使用该stage。claim/config只在新模式增加 `evidence_mode:"structured"`；不得忽略后付费。
- 新增只读 `GET /api/agent-capabilities/evidence`，精确返回 `{structured_evidence_supported:true}`，仅代表协议支持；前端另核原视觉配置与新执行器能力，不能把它当作额度或真实模型效果证明。实际404才作为旧服务不支持；其他故障明确不可核对。
- 所有模型决策、结构修复、物理重试仍计同轮TEXT账本和max_text_calls；不新增隐藏模型调用，不启纯文本fallback。预算不可核时新请求拒绝，已成功请求仍可按原冻结计划恢复；未知提交保留原key/body与模式。

## 模型决策与结果1.3

工具决策沿用原有工具与参数，不新增任意文件/网络工具；最多4步、32不同帧、inspect_clip最多12秒/2fps。新模式的answer决策精确为 `{type:"answer",answer_scope,answer_blocks,suggested_clip_instruction}`；模型不提供独立answer/citation_ids/visual_citations，也不生成时间、哈希、origin或URL。tool决策原形状不变。

每项精确字段为 `{block_id,kind,text,utterance_ids,frame_ids}`：

- block_id严格连续b01..b08，1..8项；text为包含非空白内容的1..1000个UTF-16代码单元，保留原文与首尾空白、不trim或归一化；允许TAB/CR/LF，拒绝其他C0/C1控制符及孤立代理项。下述总answer的6000上限也按UTF-16代码单元。Schema字符长度只是必要条件，三端还须执行此更严格约束。每项utterance_ids最多8个，唯一、按本轮已观察原句的原始顺序；frame_ids最多4个、唯一。非变化项frame_ids按frame_id升序。
- 仅新分项的“全空白”按JavaScript trim集合统一：U+0009..000D、0020、00A0、1680、2000..200A、2028、2029、202F、205F、3000、FEFF；其中不允许的控制字符仍先拒绝。全NBSP/BOM不是有效内容，有正文时首尾NBSP/BOM也保留。此处不改变旧问题或旧模式的文本规则。
- SPEECH：1..8个原句ID、空帧ID，必须来自本轮实际工具返回的原句。讲者说过什么、讲述原因须用此类，不能仅凭图片归给讲者。
- FRAME：空原句ID、1..4个实际已入模帧ID。只是所见画面，不证明语音或因果。
- SAMPLED_CHANGE：空原句ID、恰好2个不同实际帧，按精确PTS时间先后；两帧必须同属于本轮同一次成功inspect_clip结果，不能来自相隔很远的任意两图，也不能仅按frame_id判断时间。text应陈述两侧已见状态，原因须另列SPEECH或INFERENCE。程序固定附采样限制提示，不能用2fps证明间隙或连续动作。
- INFERENCE：至少一个原句或帧依据，仍受本项上限/已观察约束；程序固定标为推断，不能当讲者原话或已观察因果。它不单独满足VIDEO的已观察依据要求。
- GENERAL、INSUFFICIENT：两类ID数组都为空，分别表示通用补充与明确证据缺口。不得用缺少依据的空VIDEO项代替。

VIDEO必须至少有一项SPEECH/FRAME/SAMPLED_CHANGE，可同时有推断、通用补充或缺口；GENERAL只允许GENERAL项；INSUFFICIENT只允许INSUFFICIENT项。分项及程序提示组装的总answer仍<=6000个UTF-16代码单元。结构修复沿用每个决策window_index至多一次attempt=1的机会，新增提示允许改成合法只读工具补证，工具仍计原步骤/请求预算；无法补齐时应返回INSUFFICIENT。各决策的修复和物理重试都计同一轮总请求上限，不能无限自我审核或在预算耗尽后额外调用。

结果新增 `agent-answer-evidence.schema.json`，schema_version="1.3"、顶层evidence_mode="structured"、answer_blocks；provenance.prompt_version="video-agent-evidence-v1"。保留旧视觉结果的来源、question、answer_scope、citations、visual_evidence、visual_citations、tool_calls及suggested_clip_instruction等字段。

有focus时顶层含原focus_timestamp_ms，所有tool_calls含origin，首步须USER_FOCUS真实取帧；无focus不补该字段、tool_calls无origin。程序映射到原1.1/1.2完整来源/PTS/JPEG/工具并集校验后，还须完整核验本1.3分项，不能借投影绕过新字段/枚举/正文校验。

citations为所有分项utterance_ids并集，按ASR顺序，只能由程序取原句全文/时间；visual_citations为所有frame_ids并集，按frame_id排序，explanation严格由程序生成 `关联分项：b01、b03`。顶层仍严格沿用最多24个原句引用/12个画面引用，分项各自合法但总并集超限也必须拒绝，不能截断或放宽原投影校验。不能多引、漏引或让模型自行添加无关证据。visual_evidence仍为本轮全部实际已入模帧，而不仅引用子集。

程序正文逐项使用以下固定前缀，前缀后换行接text，各项以两个LF拼接，末尾无额外LF：

- SPEECH：`【原句依据 bNN】`
- FRAME：`【画面观察 bNN】`
- SAMPLED_CHANGE：`【前后采样 bNN】`，text后另换行追加`（仅比较已取样画面，不证明采样间隙或因果。）`
- INFERENCE：`【推断 bNN】`，text后另换行追加`（属于推断，不能当作讲者原话或已观察事实。）`
- GENERAL：`【通用解释 bNN】`
- INSUFFICIENT：`【证据不足 bNN】`

Java和前端重新计算并核对正文/证据并集，不信任独立answer。前端用分项卡片和纯文本显示内容，标签/采样提示由程序控制；旧回答保留原展示。历史完整结果与学习笔记支持1.3，笔记保留标签、实际引用图/时间及采样边界；新草稿模式、原未决提交模式独立，不能因修改开关覆盖原回执或误清新稿。

## 验收要求与边界

覆盖逐项缺失/错模态/未知或未观察ID/多余字段/并集篡改/自由正文篡改，变化单帧、反序、同实际位置、跨工具批次、相邻1.1/1.2旧路径兼容；真实FFmpeg取帧+受控模型演示缺一侧→有限工具补查→合法变化，预算耗尽→不足，未知响应/0预算成功重放/模式冲突/旧Worker隔离。仅把这些作为工程闭环，不冒充真实模型质量比较。

真实质量比较需另行冻结问题、必要证据时间窗、要点与不可回答条件，并区分标注来源；对比仅转写、旧固定采样视觉Agent和新分项模式，分别记录自主找位置/给定位置、正确要点/无依据断言/拒答和实际请求开销。本轮未经真实供应商验收时明确标注，不填写提升数字。已有单图USER_FOCUS真实样例也不证明自主补查效果。
