# 剪辑请求取消与继续

2026-11-06：补齐自动恢复达到上限后的操作，以及长时间等待时的取消入口。继续处理使用独立新请求，复用原视频已验证的 MEDIA/ASR；文本分析重新执行并使用新请求的次数预算。旧请求、模型调用记录和原话题草稿均保留。

## 接口与状态

- `POST /api/clip-requests/{id}/cancel`，body `{}`：仅 QUEUED/RUNNING 可取消，重复取消同一 CANCELLED 请求返回原快照；PLAN_READY/FAILED 不可取消。取消无需依赖随执行进度变化的 state_version。
- `POST /api/clip-requests/{id}/resume`，body `{"max_text_calls":6}`，携带 `Idempotency-Key`：仅 FAILED/CANCELLED 可继续。默认 6 次，范围 1～24。返回一个新请求，并增加可选字段 `resumed_from_request_id` 指向原请求。

继续请求的幂等身份包含原请求 ID 和新次数上限，同一标识重复提交不增加请求数。改变预算或来源时不能复用旧幂等标识。新请求按当前文本模型与备用模型配置创建，便于修正配置后继续；原请求的预算、供应商调用和结果不重置。

## 来源与并发

事务按原分析、剪辑 owner、stage 的顺序加锁。取消时清除对应 stage 的执行凭证，后续续租、结果发布和新的模型预留均被隔离；已经派发的调用仍能凭原派发身份结算状态及用量。取消不能承诺撤回供应商已接收的请求或消除其费用。

继续请求重新核验原分析已完成、ASR/TIMELINE 产物哈希及内容，并与旧请求冻结的视频身份、视频哈希、转写哈希和时长逐项对照。API 不在数据库锁内读取整个大视频；Worker 在任何模型出网前校验实际源文件 SHA256，源文件变化时失败且不调用模型。

V12 增量迁移仅增加恢复来源字段及索引；旧请求字段为空，原分析、审核修订、确认版本和导出不变。取消后的 owner 不会被后续状态刷新重新变成 PLAN_READY。

## 页面行为

运行或排队时显示“取消本次查找”；失败或取消后显示“继续查找”，明确说明复用转写、新建文本分析和新预算。取消保留上方未提交的剪辑要求；继续会切换请求，因此有新输入或未保存方案时需先处理这些内容。

继续的提交标识按原请求和预算分别保存在本地。网络响应丢失后再次点击复用同一标识；返回的来源、指令或预算不匹配时不替换当前视图，迟到轮询不会改写其他请求或草稿。

## 文本恢复的补充修复

HTTP 200 的空白、空对象、非 JSON 或非对象响应视为不完整响应，按原有限策略恢复，不提前发布 SUCCEEDED。识别明确的限流、临时故障错误码；参数错误不按 InternalError 前缀盲目重试，额度耗尽或认证错误优先切备用服务。分类参照 [百炼错误码](https://help.aliyun.com/zh/model-studio/error-code)与 [DeepSeek 错误码](https://api-docs.deepseek.com/quick_start/error_codes/)，不解析和公开任意供应商错误消息。

静默响应读取以短周期检查租约，不发出新的 HTTP 请求。Guard 失效后结束当前连接，保留该已派发调用的 UNKNOWN 状态，不进入下一次付费尝试。连续保活仍受原来的实际总截止时间约束。

## 验证

Java 集成测试覆盖排队/运行取消、重复取消、迟到结果拒绝、旧调用结算、恢复并发幂等、来源漂移与原分析不变。前端覆盖新旧快照、来源身份、预算、幂等标识隔离和未保存输入保护。Python 测试覆盖不完整 200 响应、业务错误分类、源文件变化时阻止调用，以及真实本地静默服务在 Guard 失效后结束等待且仅保留一次 UNKNOWN 调用。

本轮 Python 全量 1086 项及 98 项 subtests、Java 全量 215 项、前端 97 项测试通过，Ruff、类型检查和构建通过。浏览器使用已有 KV Cache 来源完成“创建（预算 6）→取消→继续（新预算 4）→再取消”，并验证取消保留未提交输入、这些输入会阻止切换至新请求。

这次控制流程验收的两个新请求均未领取执行，文本/ASR 新调用均为 0。两个请求的来源哈希相同，原分析、原话题审核、原剪辑方案及导出快照逐项不变，既有 MP4 SHA256 不变。主动取消不显示失败诊断警告。上述合成错误与排队取消验收不代表真实供应商曾发生相同故障。
