# 通用视频话题解析与人工切分

2026-10-29，当前交付目标调整为：上传视频 → AI 识别连续话题及起止时间 → 人工回看、选择和调整 → 确认后生成独立 MP4。本文优先于此前商品识别和展示版扩建计划，已有商品任务、预测、审核和成片继续保留。

参考 [DOVideo-AI](https://github.com/Xiaoc7r/DOVideo-AI) 的视频工作台、结构化内容与时间戳证据展示。本轮使用本项目已有上传、ASR、MySQL 任务、审核修订和准确导出能力，实现通用话题分段。参考项目的检索、追问和多种 Agent 模式不属于本轮交付，也不复制其代码或将商品名称简单替换成话题名称。

## 用户流程

1. 上传视频，创建话题解析任务，查看处理进度。
2. 解析结果逐段显示标题、摘要、关键词、开始和结束时间；点击可跳到原视频并查看对应转写。
3. 默认不替用户勾选。用户选择需要的段落，可修改标题与边界、拆分或补充片段。
4. 保存修订，确认所选片段，再创建正式导出。只有已确认版本中的启用段落可以导出；重复请求复用同一冻结批次。
5. 预览、下载单独 MP4；后续修改产生新修订，不改写旧成片。

例如 05:00～07:00 讨论缓存失效、07:00～10:00 讨论缓存击穿，应显示两个可选择的话题段，而不是按固定分钟数截断或按商品类别聚合。话题返场保留独立时间区间，不把同名话题自动合并为一段。

## 算法和数据约束

- 以 ASR 语句 ID 为时间锚点。模型只返回连续语句范围和话题内容，程序映射源视频整数毫秒，禁止模型编造时间。
- 使用带上下文的窗口；每条核心语句归属唯一，严格校验完整覆盖、顺序、不重复与引用范围。
- 窗口只是处理边界。首个话题可显式声明继续上一话题，必须由模型结合上一段摘要及相邻转写判断；不因标题相同自动跨窗合并。
- 每窗最多一次格式修复。保留原响应、调用账本、配置身份和失败结果；不把协议测试样本当作真实解析。
- 新建任务冻结 `analysis_mode=topics`；历史缺字段仍为 commerce，创建回执、旧结果契约及旧导出指纹保留。
- 话题预测使用独立契约，不生成虚构商品。人工审核同样独立保存原预测与修订。

## 技术路线

```mermaid
flowchart LR
    A[上传 MP4 / 断点续传] --> B[Java 创建持久任务]
    B --> C[Python 提取音频]
    C --> D[ASR 转写及语句时间]
    D --> E[文本模型识别连续话题]
    E --> F[校验引用与完整覆盖]
    F --> G[Vue 回看与人工选择]
    G --> H[保存修订 / 确认]
    H --> I[冻结时间与标题]
    I --> J[FFmpeg 编码 / MP4 下载]
```

Java 21 / Spring Boot / MySQL 继续负责任务和修订状态；Python Worker 执行 MEDIA、ASR、SEGMENT、TIMELINE 及 EXPORT_CLIP。任务领取、租约、心跳、attempt/run_token 隔离、模型调用账本和 SSE 均沿用现有协议，业务状态仍由 Java 唯一写入。

话题解析使用 10 分钟核心窗口和前后 30 秒上下文。这些值只控制模型输入量，不决定最终话题长度；跨窗续接后，一段可以跨过 10 分钟边界。每次请求包含上一话题摘要与源转写，模型只返回首末语句 ID 和章节内容。纯语音模式默认不运行 OCR，用户也可主动选择本地 OCR 作为辅助输入；这不等于使用视觉大模型理解全部画面。

工作台默认文本请求上限为 24，包含格式修复；每个非空窗口通常一次请求，协议错误最多再请求一次，耗尽预算明确失败。2 小时视频有约 12 个核心窗口，这只是请求量规划，不是耗时保证。文件 ASR 为异步处理，不按视频播放速度等待；最终时间取决于服务排队、转写、文本请求和机器编码速度。

| 接口 | 行为 |
|---|---|
| `POST /api/jobs` | 配置冻结 `analysis_mode=topics`，可选 `visual_provider=none/ocr` |
| `GET /api/jobs/{id}/topic-review` | 获取原始语句、话题草稿和已确认修订；初次均未勾选 |
| `PUT /api/jobs/{id}/topic-review` | 提交 `base_revision` 与编辑后的 `segments`；版本冲突返回 409 |
| `POST /api/jobs/{id}/topic-review/confirm` | 提交 `revision`，要求至少一个有效且互不重叠的选中片段 |
| `GET /api/jobs/{id}/topic-review/download?revision=N` | 下载不可变确认版本 |
| `POST /api/exports` | 根据确认版本、所选 segment IDs 和编码 profile 冻结批次 |
| `GET /api/exports/{id}` | 查看逐项进度，预览或下载实际成片 |

原始预测契约见 `contracts/topic-analysis-result.schema.json`。人工段保留 `origin=manual`，预测段的边界、内容被修改时分别标记来源。导出保存话题标题，不用伪造的商品字段。后续编辑不会改变已冻结批次的时间、标题和文件；历史 commerce 任务继续使用原审核 API 与导出含义。

## 验收要求

真实样本必须完整走通解析、人工选择、确认和切分；逐段核对语音引用与源时间，至少导出两个有不同讨论内容的片段并完成完整解码、时长和下载核验。测试、实际 Provider 执行、开发抽查与独立人工质量评测分别记录。未完成这些检查前，不将此需求标为完成。

现阶段不宣称精确恢复所有讨论边界。静默、转写错误、突然插话和跨窗语义仍需人工核对；已有基于语句的边界编辑和重切分用于修正这些情况。

已跑通公开课程的实际 ASR、话题模型、页面人工选择及两段正式成片。输入为 [CS50 Web — HTML and CSS](https://cs50.harvard.edu/web/weeks/0/) 官方 360p 视频从开头截取的连续 20 分钟，没有使用官方字幕、章节时间或人工边界作为模型输入。通过官方 CDN 的 96 个连续 Range 获取所需前缀，逐项核对 206 与区间后，由 FFmpeg 保留前 1,200 秒音视频；不是将不同讨论片段拼接成测试输入。开发素材和原始响应仅保存在被忽略的本地目录。

本次是开发样本流程验收，没有独立人工标注或准确率。摘要仍可能过度概括或带入常识（如标题标签摘要出现的 SEO 延伸），第 3 段标题也未充分概括前半段的 HTML 结构说明；需人工核对和编辑。结构完整、六段可定位、两份选中成片正确，不代表每个标题/摘要或所有边界都已准确。当前不承诺任意语言、静音视频、多人插话或数小时素材具有相同质量和耗时。
