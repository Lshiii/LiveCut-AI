# 按需求检索与剪辑方案

2026-10-30，用户授权实现首个文本闭环：针对已有 topics 分析，输入“把缓存失效原因和解决方法分别剪出来，保留完整解释，跳过关注引导”，返回各目标的原句证据与多区间方案，人工勾选、修改和确认后输出每目标一个 MP4。

## 首版范围

复用已完成的原始 ASR，不为每条指令重新转写。不把现有话题标题当作唯一检索来源。两阶段文本模型完成需求结构化与候选精读，默认最多预留 6 次文本请求，每阶段最多一次结构修复。2026-11-05 新增[文本请求自动恢复](./38-文本请求自动恢复.md)：保留未知旧调用，在原预算内使用独立序号进行有限重试或切换备用服务。

支持 BM25 关键词检索；明确配置本地 embedding 后，使用文档/查询向量与 BM25 的 RRF 融合。检索方式写入 provenance。配置的模型损坏应失败，不能悄悄报告为语义检索成功。首版不包含自主工具 Agent 循环或视觉取证；它们是后续单独验证的功能。

索引绑定视频哈希、原始转写哈希、切块配置与 embedding 模型身份，缓存内容另有 SHA256。候选展开相邻原句；模型只能选择该目标实际看到的 ID，程序根据原句映射时间。每个目标均有输出，明确区分 FOUND、NOT_FOUND、NEEDS_REVIEW，不能用无关片段填充缺失目标。

## 独立请求与审核

- `POST /api/jobs/{jobId}/clip-requests`：幂等创建，输入 `instruction` 与可选 `max_text_calls`（1～24，默认 6）。来源 topics 任务必须完成，绑定视频、转写与源分析身份。
- `GET /api/jobs/{jobId}/clip-requests`：列出当前来源的请求。
- `GET /api/clip-requests/{id}`：独立执行状态、预算、方案修订与原句。
- `PUT /api/clip-requests/{id}/plan`：以 `base_revision` 保存 outputs；不覆盖原话题审核。
- `POST /api/clip-requests/{id}/confirm`：确认指定 `revision + plan_hash`，至少选中一个有充分证据的输出。
- `POST /api/clip-requests/{id}/exports`：从指定已确认版本冻结导出，profile 为 `h264-aac-v1`。
- `GET /api/clip-requests/{id}/exports`：独立显示导出批次和成片。
- `POST /api/clip-requests/{id}/cancel` 与 `/resume`：取消等待或执行、从失败或取消记录建立独立新请求。继续时复用原 ASR、重新执行文本分析，保留旧预算和账本；见[取消与继续](./39-剪辑请求取消与继续.md)。

新增 CLIP_REQUEST 执行 owner，使用现有 SEGMENT 阶段、租约、执行器容量与 TEXT 调用账本；预算归新请求，父分析任务的状态、预算、预测和审核草稿不因新请求而改写。公开状态与工具证据不包含私有执行 token、模型密钥或原始供应商地址。

方案来源的媒体、ASR 与已发布结果需再次核验文件哈希及身份。确认后方案不可变，后续编辑产生新修订。UI 独立维护请求草稿、请求选择和未保存保护；迟到轮询不能覆盖其他请求或用户正在修改的方案。

## 多区间与口播排除

每个目标一个 output，包含有序的 `parts[]`。每个 part 引用 `start_utterance_id/end_utterance_id`，程序派生整数毫秒。单 output 内不得重叠，不同目标可以复用必要的原句上下文。

`excluded[]` 记录被排除的原句及原因，这些原句不能出现在同一 output 的保留区间。仅出现“关注”字样不足以判为推广，例如“关注缓存失效条件”必须按实际语义处理。正文与引导混在一句时，现有句级时间不能保证精确句内删除，应标记 NEEDS_REVIEW 并交人工处理，不生成虚构词级时间。

初始所有 output 均不勾选。NOT_FOUND 与 NEEDS_REVIEW 不得启用导出，不能以页面勾选绕过状态校验。

导出按每个目标的有序 parts 精确读取源区间，统一编码后拼接为一份 H.264/AAC MP4，不使用首尾包围区间把排除内容带回。指纹包含来源哈希、确认方案哈希、区间顺序及编码配置。manifest 保存实际源区间与预期时长总和，媒体 metadata 保存真实时长；帧边界与 AAC 容差按受限区间数累计，旧单段导出保持旧协议。

## 本地语义检索

安装可选依赖 `uv sync --dev --extra ocr --extra retrieval`，再显式执行：

```powershell
python scripts/prepare-intent-embedding.py
$env:LIVECUT_INTENT_EMBEDDING_DIR = (Resolve-Path data/models/intent-bge-small).Path
```

准备脚本下载固定 revision 的 `Xenova/bge-small-zh-v1.5` ONNX int8 转换和 tokenizer，原模型为 BAAI/bge-small-zh-v1.5。模型、来源及实际哈希只保存在忽略目录，运行时不会下载或执行远程代码。本地推理使用 CPU、CLS pooling 和 L2 归一化；模型与 tokenizer 哈希纳入模型身份。

没有配置目录时明确使用 BM25。真实 CPU 测试与真实文本供应商验收分别记录，不把 embedding 的合成相似度示例当作视频检索准确率。
