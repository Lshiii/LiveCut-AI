# 持久任务与调用预算

Java/MySQL 保存业务状态，Python 只执行计算并提交引用。当前固定阶段为 `MEDIA → ASR → SEGMENT → TIMELINE → REVIEW_READY`。OCR 属于 SEGMENT 的输入证据；识别算法保持现有 ASR + 本地 OCR + 文本模型方案。REVIEW_READY 表示可以开始人工审核，不能直接当作审核通过。

## 启动

沿用 [Java 启动说明](./07-Java视频来源服务.md)，在私有 `.env.java` 配置高熵随机 `LIVECUT_WORKER_API_KEY`。Worker 使用相同环境变量。内部请求必须携带 `X-Worker-Key`；未配置时返回 503，错误或缺失凭证返回 401。密钥不放进 URL、日志、前端或公开仓库。服务默认仅绑定本机。

```powershell
./scripts/java.ps1 -Task Verify
./scripts/java.ps1 -Task Run
```

Verify 使用独立 `livecut_test` 库；协议测试拒绝指向非测试库。开发库使用 `.env.java`，测试配置使用 `.env.java-test`。

## 外部 API

| 请求 | 用途 |
|---|---|
| `POST /api/jobs`，`Idempotency-Key` 请求头 | 使用 `video_id` 和 `config` 创建任务 |
| `GET /api/jobs?limit=20&offset=0` | 任务列表与阶段快照 |
| `GET /api/jobs/{id}` | 状态、阶段、已预留调用次数 |
| `POST /api/jobs/{id}/cancel` | 取消执行并使旧凭证失效 |
| `POST /api/jobs/{id}/retry` | 在未耗尽 attempt 时重试失败阶段 |

创建示例：

```json
{
  "video_id": "使用上传返回的UUID",
  "config": {
    "asr_model": "paraformer-v2",
    "text_model": "qwen-plus",
    "visual_provider": "ocr",
    "ocr_sampling": "uniform",
    "max_text_calls": 12,
    "max_asr_submissions": 1
  }
}
```

相同幂等键与相同标准化输入返回同一个任务；不同输入返回 409。配置在创建时冻结。新分析使用新幂等键及递增 generation。公共快照不返回 run_token 或含 token 的内部存储路径。

新建任务的 `ocr_sampling` 默认 uniform，支持 prefix 对照；旧记录缺字段时仍按 prefix 执行。新默认不会补写旧配置；旧创建请求在未显式给策略时可按原摘要恢复旧回执，显式改变策略仍冲突。详细规则及验收见 [全片 OCR 采样](./24-全片OCR采样与旧任务兼容.md)。

### 恢复操作

创建、列表、详情、取消和重试的任务快照都包含 `actions`，由 Java 根据同一份已锁定的父任务和 ANALYSIS 阶段状态计算：

```json
{
  "actions": {
    "can_cancel": true,
    "can_retry": false,
    "retry_block_reason": "ATTEMPTS_EXHAUSTED",
    "max_attempts": 3
  }
}
```

示例表示失败阶段已用完当前配置允许的执行次数。客户端使用返回值，不写死三次，不因为 `status=FAILED` 就显示可重试。`retry_block_reason` 在可重试时为 null；其他情况为 `JOB_NOT_RETRYABLE` 或 `ATTEMPTS_EXHAUSTED`。只有 FAILED 且存在失败阶段、每个失败阶段的 attempt 都低于当前配置上限，才允许人工重试。自动退避的 `last_retryable` 不控制人工重试权限。

QUEUED、RUNNING、FAILED 可以取消；REVIEW_READY 和已取消任务不再提供取消动作。对已取消任务重复调用 cancel 仍幂等返回原快照。恢复快照用于展示，不能充当授权凭证：实际 POST 在事务内重新锁定并调用同一判断器；旧页面看到可重试，也不能越过已发生的取消、成功或次数耗尽。

阶段执行次数与模型请求预算相互独立。重试不会增加、清空或返还模型请求额度，也不保证还有可用的新模型请求；某些重试可以复用已验证的缓存。新建分析是另一份任务和调用预算，不代表自动免费复用旧任务。页面按 `state_version` 丢弃同任务的迟到快照，跨任务切换仍使用任务身份与选择版本隔离。

## Worker 协议

| 请求 | 关键字段或行为 |
|---|---|
| `GET /internal/stages/ready` | `items` 中包含可领取 stage；可选 `stage_type`、父分析任务 `job_id` |
| `POST /internal/stages/claim` | `stage_id/worker_id/claim_request_id`，可选父分析任务 `job_id` |
| `POST /internal/stages/{id}/heartbeat` | `attempt/run_token`，续租不更换 token |
| `POST /internal/stages/{id}/checkpoint` | 凭证加 `checkpoint_key/checkpoint_hash` |
| `POST /internal/stages/{id}/complete` | 凭证加 `manifest_key/manifest_hash` |
| `POST /internal/stages/{id}/fail` | 凭证加安全的 `error_code/retryable` |

同一次领取使用固定 claim_request_id；领取响应丢失时重试原请求。响应包含冻结配置、源文件 key/hash、成功前序阶段的 manifest 引用、input_hash、租约和 hard deadline。不同 Worker 竞争同一阶段只有一个成功。旧领取请求不会被拿去领取新 attempt。

指定 `job_id` 时，Java 在父任务锁内再次核对 stage 归属；不匹配返回 409 / `CLAIM_TARGET_CHANGED`，不创建 receipt 或增加 attempt。目标也参与领取请求的幂等指纹，重放时不能删除或更换目标。未指定目标保持原指纹与行为；EXPORT_CLIP 同样按父分析任务过滤。对应 Worker 参数及显式 ASR 复用见 [复用说明](./16-ASR转写复用.md)。

默认租约 90 秒、hard deadline 1800 秒、最多 3 次 attempt。Java 每秒回收过期工作并经过 RETRY_WAIT 退避；Python 不自行修改重试状态。可通过 `LIVECUT_JOB_LEASE_SECONDS` 等配置调整，实际配置名称见 application.properties。hard deadline 不被心跳延长。

同一成功 attempt 的同一 manifest 重复回调返回 ALREADY_APPLIED，不重新推进。不同结果哈希返回冲突；旧 token 返回 STALE_ATTEMPT。回收和完成通过父任务锁串行决定；没有被回收且未超过 hard deadline 的迟到完成仍可被接收。所有阶段写入按 job → stage 顺序加锁。

当前真实 ASR 仍为一个分片。协议测试注入两个合成分片验证汇合条件，不代表已实现真实多分片转写。结果路径约束在 `jobs/{job}/stages/{stage}/attempts/{attempt}/{run_token}/` 下，manifest 固定名为 manifest.json。

## 调用账本

`POST /internal/model-calls/reserve` 原子预留一次请求额度。请求与 stage、operation_key、input_hash、model_id 和调用类型绑定。相同 operation 的重试返回原记录，不能通过换 request_id 再计一次额度。

`POST /internal/model-calls/{request_id}/update` 更新外部调用状态。只有 RESERVED → DISPATCHING 并收到 `outcome=UPDATED` 才许可发起新付费请求。重复 DISPATCHING 返回 ALREADY_APPLIED；UNKNOWN_OUTCOME 不可重新派发，也不释放额度。ASR 保存 provider_task_id 后优先恢复查询。

已派发 attempt 的迟到回调可结算它自己的调用记录，不能覆盖新的阶段结果。已写入的 provider_task_id、usage 指标和响应引用保持不可变；响应文件在本地私有目录。请求数预算不是人民币金额或供应商实际账单，不声称网络中断时具有供应商侧 exactly-once 保证。
