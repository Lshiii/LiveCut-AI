# 普通话题分析复用转写重新执行

2026-11-06：将已完成 MEDIA/ASR 的安全复用接入普通网页分析。原阶段的文本尝试次数或恢复窗口耗尽后，继续把同一阶段设为 READY 不能增加可用尝试；而新建完整分析会重新提取音频和转写。新增一个明确的新分析轮次，保留旧记录并复用准备产物。

## 页面与接口

`POST /api/jobs/{id}/resume-from-asr`，body `{"max_text_calls":12}`，携带 `Idempotency-Key`。源任务必须是 topics，状态为 FAILED、CANCELLED 或 REVIEW_READY，且唯一的 MEDIA/ASR 阶段均已成功发布。页面提供“复用转写重新分析”，默认新文本预算 12，范围 1～100；接口保持普通任务预算 0～100 的语义，0 不允许新的文本请求。

成功响应是一个新的任务和 generation，不代表已复制完准备产物。新任务的 MEDIA 先进入 READY，其余阶段按依赖解锁。新任务冻结源 ASR 模型与原分析的 OCR 等配置，文本模型和备用名单采用当前部署配置，ASR 预算强制为 0。原任务、旧调用、原预测、人工修订和导出均不改写。

公开快照增加可选 `resumed_from_job_id`；actions 增加 `can_resume_from_asr` 和 `resume_from_asr_block_reason`。阻止原因为 `RESUME_REQUIRES_TOPICS`、`JOB_NOT_RESUMABLE`、`PREPARATION_NOT_READY` 或 `PREPARATION_SOURCE_INVALID`。这些能力是快速元数据判断，POST 仍在事务中重新核验来源。

普通“重试失败阶段”遇到 `TEXT_RETRIES_EXHAUSTED` 或 `TEXT_RETRY_DEADLINE_EXCEEDED` 时返回 `TEXT_RECOVERY_EXHAUSTED`，引导建立新轮次，不再反复排队同一个已经耗尽的文本操作。其他失败保留已有的缓存恢复路径。

## 执行链路

```mermaid
flowchart LR
  A[已有音频和ASR的终态任务] --> B[Java校验并冻结来源]
  B --> C[新任务与新文本预算 ASR预算为0]
  C --> D[MEDIA 校验复制audio和media_info]
  D --> E[ASR 校验复制原transcript]
  E --> F[重新执行文本话题分析]
  F --> G[结果校验与新的人工草稿]
```

创建事务先锁视频，再锁源任务和源阶段，与普通创建的 generation 分配顺序一致。来源包含视频身份与哈希、原代次、ASR 模型、两个已发布 manifest 的路径和哈希。来源 JSON 单独持久化，仅在经过鉴权的 Worker claim 中下发为 `config.preparation_reuse`，不进入公开 config 或快照。结构见[共同契约](../contracts/preparation-reuse.schema.json)。

Worker 拒绝链接、重解析点、越界路径及不匹配的 manifest 身份；验证实际视频 SHA、产物哈希、ASR 模型和时间。MEDIA 复制音频与媒体信息，ASR 复制转写原字节，语句 ID 与时间不改变。复制在当前 attempt 的 staging 目录完成，校验后原子发布，产物使用新任务身份写入 manifest。重复执行只接受已经存在的相同内容。

这一复用模式的依据是已发布产物，不重新运行 ASR raw-result 的映射，不要求 source 的原始供应商 checkpoint。来源本身也可以是上一次复用后的任务，支持多轮继续。原有 CLI 的严格 raw 等价复用协议保持独立；不能同时使用两种来源配置。

## 失败与预算

来源文件缺失、哈希变化、模型或音频不匹配时明确停止，不自动转为上传或付费 ASR。Java 的零 ASR 预算是额外的硬限制。复制和 Worker 最终产物校验按块检查取消与租约，写 manifest 前再次检查；每个复用阶段只对实际源视频作一次可取消哈希遍历。

新文本请求、重试与备用调用共享新任务预算；原未知调用仍保留原状态，不能清空旧策略文件来换取“免费重试”。网页按来源和新预算保存幂等回执，网络结果未知时再次点击复用同一标识；返回身份、预算或 lineage 不匹配时不切换当前视图，双编辑器草稿和迟到快照保护仍生效。
