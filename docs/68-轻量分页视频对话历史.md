# 轻量分页视频对话历史

当前完整列表最多返回100个会话。每个会话携带全部轮次与成功回答；服务端还从数据库读取冻结source_json、history_json等列，并逐轮读取阶段，列表期间持有analysis_job行锁。前端随后又读取已选会话详情。真实4会话、5轮样本中，完整列表22595字节，已选详情3517字节，已选会话同时出现在列表中；这是响应体UTF-8字节，不代表网络传输时间或模型费用。

## 用户流程

“对话记录”按页显示首个问题、创建时间、轮数和进行中数量。上一页、下一页与回到最新只浏览历史，保留当前回答、问题草稿、请求上限、定位、原句选择与原提交。选择其他会话仍需先处理未发送草稿，完整详情读取并通过来源校验后才用于提问、回看、笔记和剪辑。

首屏默认选择最新会话；当前选择不在历史页时继续独立显示。历史刷新不能代替用户换会话，不用摘要清回执或确认业务结果。空会话显示“新对话”，未加载全文的会话不能伪装成空turns的完整会话。

## 接口与字段

新增只读GET `/api/jobs/{jobId}/agent-session-history?limit=20&cursor=...`，原完整列表接口保留。默认20条，limit仅1～30的整数；输出契约为[agent-session-history.schema.json](../contracts/agent-session-history.schema.json)。

页面字段固定为schema_version=1.0、job_id、items、limit、next_cursor、active_count。每项包含id、job_id、video_id、created_at、source（video_sha256、transcript_hash、duration_ms）、first_question（首轮完整问题，空会话为null）、turn_count（0～100）和active_turn_count。active_turn_count只计QUEUED/RUNNING且不大于turn_count；active_count计整个任务VIDEO会话的活动轮次，不限当前页和ceiling，不含字幕校对。

只投影上述元数据，不读取转写、话题、history_json、result_json、模型回答、工具轨迹、阶段大JSON或密钥。source是列表来源提示，不能代替已验证Session，也不用于认领未知提交、发起提问、准备锚定、导出笔记或授予权限。

不存在任务返回404 JOB_NOT_FOUND；坏limit返回400 INVALID_AGENT_HISTORY_LIMIT；坏、超长、跨任务、跨kind或边界不可用的cursor返回400 INVALID_AGENT_HISTORY_CURSOR。cursor仅是不透明分页位置，不是访问凭证。

存储元数据不符合公开不变量（坏来源摘要、时长、非空会话缺首轮、超出轮数等）返回409 AGENT_HISTORY_INVALID，不拼造合法200。跨字段约束、同任务/来源与排序仍需程序核验，Schema不是完整证明。

## 分页与只读查询

按不可变(created_at,id)倒序keyset，多取1条判断后页。首屏最高tuple作为ceiling，下一页位于ceiling以内且严格早于上一页末尾。时间保持数据库DATETIME(6)微秒，UUID按ascii_bin字符串顺序比较；前端不能用截断微秒的Date.parse验证顺序。服务器核对游标中真实VIDEO边界、所属任务、精确时间与合法关系。

ceiling只是跨请求范围上界，不是冻结成员集合：晚提交或回填的旧时间tuple仍可能进入未读范围；回到最新重新建立边界。状态变化、提问新增轮次不改变会话创建顺序。

新服务使用独立只读REPEATABLE_READ事务，使页面、页内计数和全任务active_count在同一一致性快照读取。无FOR UPDATE、不调用完整sessionSnapshot或源文件验证。页内轮数批量查询，不逐条查询阶段；复用已有session与turn索引，无必要不增加迁移。固定查询条数不代表扫描只与页大小有关，kind过滤及全局活动数须检查实际执行计划，不能据此宣称数据库O(page)、吞吐量或延迟提升。

## 前端、兼容与原提交

元数据页、当前游标/页栈、已验证完整Session缓存分别持有。新摘要不能强转完整Session；首次选择或已有选中刷新仍通过完整GET及原解析/单调合并。翻页有独立读代次，迟到旧页不能替换当前页、当前来源或已选回答；隐藏时停止/隔离读取，返回核对当前页和已选详情。全任务active_count与当前选中详情共同决定5秒/60秒刷新；不让未再读取的旧完整缓存把已终态会话永远当作活动。

只有新端点实际HTTP404才兼容旧完整列表，兼容项需完整解析后才可进入原缓存；网络错误、5xx或畸形200均保留已有好页，不退回大列表。旧服务兼容明确提示最近100条上限，不能称其已具备新分页或小响应。手动检查升级不能把用户正在看的旧页偷偷切到最新，需明确回到最新。

不可变v1回执继续按job扫描，与分页独立。旧livecut-agent-turn-{sessionId}槽只有key/input，必须按需读取完整Session确认所属来源后才能按原复制/复读迁移；不能因为会话未在当前页而漏掉、删除或用metadata补造source。迟到读取不得对新来源迁移；故障与未知归属保留原槽，明确阻止可能重复的新提交并提供重试。其他任务的槽不迁移到当前任务。无需旧槽时不为了迁移预读全部历史全文。

旧槽归属缓存只绑定本页owner生命周期及完整slotKey/raw，读取并发有界。发送入口在创建回执前后都重新枚举实际槽，不能只依赖storage事件或此前UI状态；其他页面新增或修改旧槽后必须重新核对。新选目标未取得经校验全文时（含读取失败）禁止发送，不能把selected=null误当作应新建对话；保留原会话直到新详情核对成功，或用户明确选择“保留当前会话”。已有有效全文的普通刷新失败保留原行为，实际提交仍服从原来源、回执与服务端原子校验，摘要不能授予新权限。

会话所属任务与来源经现有API创建后不可修改。同一owner和原始槽内容下，已通过完整GET核验的归属可以跨隐藏保留，避免返回时重复读取其他任务的全文；隐藏仍会隔离未完成读取，不能迟到建立新证明或迁移。切来源重建缓存，槽内容变化必须重核。

## 验证范围

前端覆盖严格摘要解析、页次与迟到、选中详情独立、草稿/原回执/定位保留、仅真404兼容、错误不降级、活动刷新与旧槽按需核验。真实浏览器检查列表和详情、桌面/320px，以及受控107会话多页和跨页选中；全部POST默认拦截，不新增ASR或模型请求。完成后更新实际验收记录与README截图。
