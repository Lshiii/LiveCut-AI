## 实际已验证

- 实际调用 paraformer-v2，返回 97 条语句，时间覆盖 0–599980 毫秒；保存 provider task_id 后可复用，重复执行读取结果而非再次提交。
- 实际调用 qwen-plus，默认从转写自动发现商品，未使用假响应代替真实调用。

## 失败与调整

第一次文本调用将不同颜色面膜拆成多个款式，又给 identified 区间分配多个产品标签。一次格式修复仍失败，校验器拒绝该结果。原始失败响应保留。

随后将默认发现粒度明确为商品类别，同类别不同颜色统一归组。重跑结果结构合法，但只发现面膜，自动预测区间为 0–540261 毫秒，余下 540261–599980 毫秒判为非商品内容。

独立查看画面发现中段已经出现保湿霜介绍，因此该文本基线发生漏检/错误延续。ASR 对“舒芙蕾”等商品名称有近音误识别，不能把结构合法解释为商品切分准确。

## 后续验证

提前加入少量视觉观察，以实际帧时间和可见商品类别/字幕作为证据，再让语义模型定位讲解。视觉证据与语音可以冲突，不能直接把画面出现时间当讲解边界。

不从这一份样本计算宣传性准确率，不报告尚未核定的人民币费用；保留 token 用量与失败调用记录。后续视觉结果另行追加，不删除这一轮失败记录。

## 本地 OCR 与独立发现的开发过程

视觉 API 首批调用失败，返回 `AllocationQuota.FreeTierOnly`；没有取得可用于本轮结论的真实 VLM 结果。用户选择本地 OCR + 文本模型，保留账户计费设置。

安装 RapidOCR 3.10.0 / ONNX Runtime 1.31.0，在 CPU 上按约 45 秒间隔读取 14 帧。实际时间使用 FFmpeg 源帧 PTS，记录请求位置与实际位置，帧不放大到超过原分辨率。OCR 保留原文、置信度过滤和帧引用，不把 OCR 文字伪装成视觉模型识别的商品类别。

第一轮 OCR + 单步分段结构合法，但仍把前 540 秒合成面膜；生成的九分钟预览是已知错误结果，不能作为可用面膜切片交付。随后以当前窗口的转写和 OCR 进行独立发现，同一文本模型能发现面霜，说明存在前窗已知类别造成的错误延续。

将独立商品发现与区间分配分开后，模型能够发现面霜，但长列表语句 ID 出现跨越其他商品、`identified` 引用多个商品等错误；一次格式修复仍未通过，流水线中止，没有导出该轮结果。

再改为首尾语句 ID，由程序展开连续语句；一轮调用遗漏过渡句，修复后仍遗漏。随后将具体缺失 ID 写入修复提示，强调过渡和闲聊也须覆盖。每轮使用新目录保存模型响应与调用账本，未用人工边界替换预测。

这些是同一开发样本上的迭代，不是独立测试集的效果提升。默认 OCR 证据不能自动证明商品身份，所有预览仍保留 DRAFT 和人工审核要求。

## v6 实际运行结果

`catalog-free-anchors-v6-explicit-coverage` 在同一真实视频上完成 OCR → 已完成 ASR 缓存 → 独立发现 → 连续区间分配 → 契约校验 → 预览切片。本轮文本调用 8 次，无格式修复；调用账本合计 input 24554 / output 3198 / total 27752 tokens。以上仅为本轮文本用量，未包含先前开发失败、诊断请求及 ASR，不据此估算总费用。

预测发现面膜、面霜、妆前乳三个标签，生成 15 个区间，其中 9 个被模型标为已识别商品讲解。默认最多导出前 6 个候选，全部实际导出并完整解码成功，ffprobe 实测长度与请求长度差 9～31 毫秒。这只能证明媒体输出可用，不能代替语义质量审核。

### 已知错误与未决项

1. 09:00.261–09:18.368 的“妆前乳”很可能是误发现：转写只说妆前使用“它”，没有足够证据证明介绍了新的妆前乳商品。
2. 面霜在 07:09.833–07:28.705 的延续讲解被判为非商品，主区间末端可能提前。
3. 面膜的购买数量/送礼讨论 01:54.149–02:21.520 被判为非商品，可能漏掉相关答疑。
4. 开头同一面膜话题被短暂闲聊拆成多个片段，可能过度分段；目前不能把所有列表项都称为真实返场。
5. 07:28.705–08:30.842 的面膜区间包含休息等闲聊，候选片段不够紧凑。
6. OCR 只能读到部分横幅，当前没有逐帧商品验证；不少候选保留 `INSUFFICIENT_VISUAL`。无采样帧的区间也不能解释为已获视觉确认。

结论：真实视频能够在无预置清单的条件下产出面膜、面霜的独立可播放候选，核心链路具备继续实现持久任务与人工审核工作台的基础。当前效果不足以宣称自动精确成片；尚无垃圾袋真实案例、独立测试集、F1 或人工审核耗时数据。
