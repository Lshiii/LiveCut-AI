# OCR 证据时间对齐与请求审计

2026-10-26。修复文字模型输入中 OCR 证据的跨时段关联；不改变帧采样、商品输出 Schema、严格逐句分类或 Java 任务状态协议。

## 已复现的问题

[上一轮完整分析](./25-全片OCR完整分析与导出验收.md)使用全片最近 ASR 中点选语句，再根据该语句是否出现在窗口上下文中路由 OCR。长句跨界时，帧本身可能在上下文之外；长静默时，也可能把远处画面文字关联给很晚的语句。旧模型输入没有实际帧时间，只有近邻语句 ID。

对同一 30 分钟开发录像的 285 条 ASR、16 帧真实观察，原算法重建 21 个帧—窗口关联。其中 08:26.273 的帧因语句 08:25.625–08:38.122 跨界，被额外送入从 08:30 开始的上下文，越界 3727 ms。重建绑定已发布源、结果、OCR 产物和旧源码摘要，不是额外捕获的旧上游请求正文，也没有证明该关联造成商品误判。

另用合成输入复现约十分钟错位及窗口内长静默；这些只证明程序边界问题，不冒充真实录像错误。

## 新关联规则

窗口显式保存原视频整数毫秒的 `core_start_ms / core_end_ms / context_start_ms / context_end_ms`。上下文裁剪到视频范围；跳过无核心语句的窗口后，仍保留原名义时间，不能按压缩后的列表序号推算。ASR 核心归属仍由中点唯一确定，不改变分类范围。

帧进入模型输入必须同时满足：

1. 实际 `timestamp_ms` 落在窗口半开上下文 `[context_start_ms, context_end_ms)`。
2. 近邻只能从该窗口的可见 ASR 中选择。
3. 到语句区间的距离 `max(start_ms - timestamp_ms, timestamp_ms - end_ms, 0)` 不超过 5000 ms。长句内部距离为 0，不因离中点较远而被误丢。

同距时，依次优先真正包含帧的半开语句、中点更近的语句、稳定语句 ID。5000 ms 是版本化的固定基线，不是语义相关性、音画一致性或识别质量阈值，也没有通过独立质量集调优。

无法关联的帧不进入该次语义请求，但原观察、图像和最终 `frames` 留档不删除。长句跨多窗而仅有一个中点归属窗时，某些帧可能被保守过滤；不承诺每帧都会发给模型。本开发录像仍有 16 个不同帧获得合法关联，关联总数为 20，窗口越界为 0。

## 模型输入与兼容

类别发现和逐句分类均携带相同 `time_context`、转写真实起止时间及筛后的 OCR 列表。每项 OCR 包含 `frame_id / timestamp_ms / presented_category / observed_text / visibility / near_utterance_id / near_utterance_gap_ms`，不发送本地对象路径或执行凭据。提示词明确：时间只用于理解证据，近邻 ID 不是商品语义证明，不得跨时段借用 OCR；正式输出仍只能按核心 ASR ID 分类，不能生成边界时间。

提示词升级为 `catalog-free-v12-time-aligned-evidence`，pipeline 为 `catalog-free-visual-text-v7`，输出协议仍为 `keyed-classifications-v2`、结果仍为 Schema 2.0。`visual_alignment` 的规则版本和 5000 ms 上限进入配置摘要。旧同目录检查点明确拒绝 `INVALID_CHECKPOINT`，不静默恢复、不迁移或覆盖旧响应；已发布旧预测、审核版本和成片仍保留。原 OCR 缓存身份没有改变，视觉观察可以经过原完整性校验继续复用；新语义请求按实际 endpoint/body 单独记账。

v12 提示词与输入体改变后，旧失败任务的新 attempt 不能承诺复用 v11.1 的模型响应。重试仍受原任务剩余额度约束，预算不足时明确失败，不自动提高上限或重置账本。
