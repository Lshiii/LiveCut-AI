# 商品身份引用与同义名称归并

> 下文保留 v13 的实现及真实运行记录；后续 v13.1/v13.2 增强一次修复中的重复声明反馈与可信语句定位，见 [协议补充](./14-逐句分类协议.md#v132修复提示绑定原标签与可信语句)。

2026-10-27。独立商家验收暴露出跨窗口按名称精确匹配的限制：相近的洗碗精、口腔喷雾名称被注册为多个商品。本次为现有分类请求增加显式身份引用，保留独立发现、原始提议与源 ASR 时间；不使用商品关键词映射表，不增加第三个模型阶段。

## 协议与执行

两步模式先从当前转写和局部 OCR 独立发现类别。该请求没有 `known_products`，第二步逐句分类才接收本次分析已接受的有限目录。

`known_products` 每项包含 `product_id / category / variant_description / aliases / identity_granularity`，取最近创建的最多 64 个实体、每项最近 8 个别名。列表与别名均为本窗口开始前的独立快照；完整别名仍在结果中保留。

分类输出的商品声明升级为四个必需字段：

```json
{
  "label": "tmp1",
  "category": "洗碗清洁剂",
  "variant_description": "",
  "canonical_product_id": "product-0001"
}
```

`canonical_product_id` 只允许 `null` 或当前输入快照中精确存在的 ID。`null` 表示没有提出语义复用；程序仍按规范化名称精确复用已有实体，在 category 模式下也匹配此前已接受的别名。未下发的旧 ID、未来 ID、空字符串、其他类型和缺字段均拒绝。

category 模式允许模型提出同类别的不同名称归于已有 ID；首次名称与 ID 保持稳定，新提议按规范化结果去重追加至 `aliases`。若提议名称已属于另一实体，则拒绝交叉引用。同窗口多个临时标签不能解析为同一已有身份，应先合为一个临时商品。

observable_variant 模式只有规范化 category 与 variant_description 均精确一致时才可引用。不同规格、类别粒度与明确款式之间不得复用；语义相似但无法精确对齐时保留新提议。这不会自动合并过去已建立的两个实体，也不解决同窗口新名称的语义去重。

全部分类通过后才更新目录，只有被核心语句引用的提议会创建实体或添加别名。原提议和引用留在私有 raw/accepted window。公共结果继续使用 Schema 2.0，Java、前端与审核/导出契约不变。

区间仍由源 ASR 顺序和时间生成，中间其他商品或闲聊不能因身份归并被吞掉，返场保留独立区间。只有相邻且分类身份相同的语句才按原规则合并。

## 校验、预算与恢复

- 分类值仍严格只有 `content_kind / product_labels`；模型不得输出时间、索引或 identity_status。
- 初次分类与一次格式修复使用同一目录快照；非法引用进入现有受预算约束的修复，不静默改为新商品。
- 两步模式每窗仍至少两次请求，修复计入同一 TEXT 上限；没有新增 ASR 或视觉请求机制。
- 配置摘要包含身份引用版本、64/8 输入上限和 variant 精确匹配策略。prompt 为 `catalog-free-v13-product-references`，output_protocol 为 `keyed-classifications-v3-product-references`，pipeline 为 `catalog-free-visual-text-v8`。
- 新代码拒绝旧配置的同目录恢复，需新目录或新分析代次；旧 Schema 2.0 已发布结果继续可读。改变请求指纹不能保证旧失败任务还能在原预算内重跑。
- 同配置恢复按已持久响应重新校验和重建目录，不重复添加别名或外发已完成请求。

## 合成验证

全量 Python **750 passed、98 subtests passed**，Ruff 通过。新增 30 项 HTTP Mock 覆盖同义返场、其他商品/闲聊隔离、新类别、64/8 裁剪、别名留档与去重、缺失/错误/未知引用、身份冲撞、重复标签、修复预算、款式隔离、未用提议和恢复。

这些测试证明协议、状态和时间约束；合法 ID 仍可能语义误配，商品条目减少不能当作识别精度提升。

## 真实 30 分钟验证

沿用 [独立商家验收的归一化副本](./28-独立商家素材完整验收.md)，源 SHA256 为 `9753505deb6d8d18e20ee651a17b454946b0e14de5bc9480c3300bcd096b5aff`，前 600 ms 补黑的来源说明继续适用。新任务 `a827c008-f604-434d-be6c-842251acb773` 为 generation 2，冻结 TEXT 30、ASR 新提交 0；明确从 generation 1 的已发布结果复用 307 条转写，并命中本素材 16 帧 OCR 缓存。

四阶段均 attempt 1 成功，最终 `REVIEW_READY`。10 窗全部完成，实际外发 20 次文本 POST（10 次独立发现、10 次分类），没有格式修复和新增 ASR；文本 usage 为输入 90,554、输出 15,354、合计 105,908 tokens，不换算费用。SEGMENT 用时 352.062 秒是这一次缓存复用运行的记录，不作为冷运行基准。

只读审计核对实际外发 body 摘要、endpoint 与持久输入身份、20 条成功调用账本的响应和 usage；ASR 复用绑定源 MEDIA/ASR manifest、音频、转写、原始响应及 checkpoint。全部阶段 manifest 与文件摘要、307 条语句恰好一次的分类覆盖和源 ASR 时间边界也通过检查。

另用独立目录实现按 accepted window 顺序重建历史身份，逐项比较真实分类输入的 64/8 快照，再以生产纯函数重建结果。两者的商品目录一致，生产重建的 products/segments/frames 与最终结果完全一致。独立发现实际输入没有旧目录；25 个合法显式引用声明中，24 个被核心分类使用，未用声明未更新目录。

真实结果保留了三个新别名：

| 首次身份 | 新别名 |
|---|---|
| 洗碗精，`product-0001` | 洗碗清洁剂 |
| 口腔清新喷雾，`product-0003` | 宠物口腔清洁喷雾、宠物口腔喷雾 |

新预测为 7 个实体、116 段（67 讲解、49 非商品），上一轮为 12 个条目、108 段。这是不同提示词的预测结构变化，**不是准确率、误合并率或返场正确率提升**。仍有“宠物用品”等宽泛条目，“洗碗巾”“宠物用洗衣精”需要结合原音复核，不强行靠名字合并。

本轮没有初始化新审核或创建新成片；正式导出闭环沿用上一轮记录。原 43 个公共业务资源和 892 个既有文件保持不变，旧预测和已确认成片未被重写。证明文件位于被忽略的 `data/runs/product-identity-references/`，包含实际请求、只读分析/目录对账、原始预测及未评分定位审计。

## 边界

固定快照限制输入增长，也意味着较早且未下发的同义名称可能仍分散；精确同名及已接受别名可在全目录复用。该实现不是检索系统，不声明向量召回、商品知识库或真实 SKU 消歧。

独立发现提示词仍按类别发现，observable_variant 的细分依赖分类阶段的明确语音证据。单步 CLI 没有独立发现请求，不能套用两步模式的抗旧主题锚定说法。
