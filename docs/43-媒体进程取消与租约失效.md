# 媒体进程取消与租约失效

2026-11-06：将 Worker 的取消和租约检查接入正在运行的媒体子进程。原先部分探测、抽音频、导出和抽帧只在命令前后检查 guard，命令内部同步等待可持续至原超时，任务已经停止时仍可能占用本机计算资源。

## 覆盖链路

| 环节 | 本轮检查位置 |
| --- | --- |
| MEDIA | 来源哈希、媒体探测、抽音频、音频验证、媒体信息发布 |
| EXPORT_CLIP | 来源与输入绑定、单段或多段转码、输出探测、完整解码、checkpoint 和 manifest 发布 |
| OCR | 默认 FFmpeg 抽帧、帧及证据哈希、证据 JSON 发布；自定义 extractor 保留原签名 |
| 共用文件 | 大文件按块哈希、阶段产物验证及原子 JSON 替换 |

媒体接口增加可选 `guard=` 回调；Worker 传入当前 StageContext 的 guard。未传 guard 的直接 CLI 调用保留原同步执行路径和错误码。Java 仍是状态与容量的唯一写入方，媒体进程不会自行把取消改成成功或释放别人的阶段租约。

## 运行与清理

受控路径使用直接 Popen 子进程，每次等待最多 0.2 秒，然后检查 guard 和本条命令的单调时钟截止。stdout/stderr 写入本次独立临时文件，不使用可能被后代继承后迟迟不结束的管道；子进程正常退出后按观察到的文件大小读取并解码，避免追随后续追加写入。

取消、执行器停止、租约失效、命令超时或中断后，仅对本次创建的直接子进程执行有界 terminate/kill/wait，再传播原始失败。未确认清理完成会在原异常上附加诊断；本轮不通过扫描进程名或任意 PID 清理其他进程，也不宣称终止包装器的整个后代树。部署应使用实际 FFmpeg/ffprobe 可执行文件。

每个命令仍受其原超时限制，整个阶段还持续受 guard 的硬截止限制。0.2 秒是 guard 已失效后的本地轮询间隔，不代表用户点击取消到进程退出的总时延；Java 状态还需要经过原有心跳回调传播到 Worker。

## 发布边界

发布音频、视频、帧图、媒体信息与 checkpoint 前再次检查 guard，失败时清理本次临时输出并保留已有目标文件。如果取消恰好发生在原子替换之后，完整成片可能已存在于当前 attempt 的隔离目录；最终阶段检查仍禁止发布成功 manifest 或 complete 回执，文件不能被当成已确认成功导出。后续复用仍须经过原身份、哈希及完整解码校验。

## 验证记录

独立公开适配器回归使用明确的合成子进程，覆盖探测、音频、单段、多段、OCR 与发布瞬间取消；验证直接子进程已退出、旧目标不变、临时文件清理、没有成功回执。额外的包装器后代继承 capture 句柄场景使用测试独有 release 文件退出，验证清理不依赖后代 EOF；未进行进程名扫描或终止其他进程。

使用本机已安装的真实 FFmpeg、实时读取的合成 lavfi 输入和 null 输出进行组件验收：在 0.5 秒触发停止或丢租时，分别约 0.625 秒返回 WORKER_STOPPED/LEASE_LOST；0.4 秒命令截止约 0.406 秒返回 PROCESS_TIMEOUT。三次均确认本次直接子进程结束并回收，没有模型或 ASR 调用。这是组件测试条件下的结果，不作为视频处理性能或页面取消总时延承诺。

本地全量 **1317 项、101 项 subtests 通过**；1 项仅适用 POSIX 的忽略 SIGTERM 后升级 kill 测试在 Windows 跳过，Linux CI 会执行。Ruff 与 diff 检查通过。独立公开适配器的 19 项回归与 Worker 阶段取消矩阵均通过；原分析、审核与导出继续按基线逐项核对。最终全量与无跳过要求以本轮提交的 GitHub CI 为准。
