# 证据核查摘要

## 解决的问题

分项证据模式的真实开发小样暴露了一个缺口：模型只接收用户附加位置的一张截图，没有查询原句，却写了“本轮未检索到讲者解释”。实际转写中存在相关讲解。因此不能把模型措辞当作“已检索且无匹配”的执行证明，合法分项也不能证明问题已经回答完整。

本轮先补只读可观测性：直接从已经验证的 1.3 结果派生核查摘要，在回答上方和学习笔记中说明实际记录了什么。摘要不读取问题关键词来猜用户意图，也不解析模型解释来决定执行状态。

**本功能没有实现强制补查或答案语义审核。** 自动补查需要另行冻结执行策略、能力隔离、预算与恢复规则，不能为了让旧轮次“更聪明”而修改其既定 SYSTEM、请求计划或成功响应缓存。

## 使用方式

1. 在视频对话中选择「结合画面」和「分项证据回答」，按原流程发送问题。
2. 回答上方会显示「证据核查摘要」，先看原句核查状态，再阅读具体分项。
3. 展开统计可看检索、上下文、话题工具轨迹，以及取得、引用和推断使用原句的不同计数。
4. 需要保存时，学习笔记也带有同一规则派生的摘要。旧版回答继续按原规则显示和导出。

原句不足时可先使用已有「原句搜索」核对相关内容；该搜索是明确的只读操作。摘要本身不会替用户发起搜索、新问答或剪辑。

## 派生规则

输入仅为已通过原有身份、来源、结构和时间校验的 1.3 `structured` 结果。Java 在笔记渲染时计算，前端在已验证结果的分项组件中计算；不把它作为独立结果校验器。1.0 / 1.1 / 1.2 没有该摘要。结果 JSON、`answer`、结果 hash、数据库记录和提交身份均不改写。

状态按以下顺序判定；状态不是回答正确性评分：

| 状态 | 判定 | 能说明什么 |
| --- | --- | --- |
| `SPEECH_CITED` | 存在 SPEECH 分项 | 有讲者原句分项，可回查来源；不证明引用支持该文字或问题已完整回答 |
| `SPEECH_NOT_CITED` | 无 SPEECH，但检索或上下文轨迹返回过原句 | 已取得原句但无讲者原句分项；原句可能只用于 INFERENCE |
| `NO_UTTERANCES_RETURNED` | 有检索或上下文轨迹，其返回原句并集为空 | 轨迹没有记录可用原句；不能区分无匹配、工具错误、重复调用或上下文额度不足 |
| `TOPIC_ANCHORS_ONLY` | 以上均不满足，存在话题工具轨迹 | 原句相关轨迹只有话题路径；仍可存在视觉工具，不等于调用过原句检索或上下文，返回锚点也可能为零 |
| `NOT_REQUESTED` | 以上均不满足 | 本轮没有请求原句检索或上下文；不能据此说视频没有相关讲解 |

例如仅话题工具返回原句且 SPEECH 引用该句时，状态为 `SPEECH_CITED`，检索/上下文次数仍为零；不能隐藏实际引用，也不能把话题锚点获取说成全文检索。话题返回原句、检索空返回且无 SPEECH 时，则为 `NO_UTTERANCES_RETURNED`，同时保留话题取得计数。

计数字段：

| 字段 | 定义 |
| --- | --- |
| `search_transcript_calls` / `read_context_calls` / `list_topics_calls` | 各类工具轨迹步数，不表示每步执行成功 |
| `returned_utterance_count` | 全部工具轨迹返回原句 ID 的去重数 |
| `search_context_utterance_count` / `topic_anchor_utterance_count` | 对应路径各自返回的去重原句数；可重叠，不能相加 |
| `citation_count` | 顶层原句引用去重数 |
| `speech_block_count` / `speech_utterance_count` | SPEECH 分项数及这些分项原句 ID 的去重数 |
| `inference_utterance_count` | INFERENCE 分项原句 ID 的去重数；不是讲者原句分项 |
| `user_focus_tool_calls` / `model_visual_tool_calls` | 用户附加位置与模型选图各自的工具轨迹数；无 focus 的视觉工具来自模型选择 |
| `user_focus_frame_count` / `model_frame_count` | 各来源轨迹返回的去重帧数；复用帧可同时属于两组，不能相加，也不是新取帧或计费次数 |
| `observed_frame_count` / `visual_citation_count` | 实际已入模帧与实际引用帧各自的去重数 |
| `sampled_change_block_count` / `insufficient_block_count` | 前后采样与证据不足分项数；即使存在 SPEECH，缺口仍独立保留 |

固定边界提示：本摘要仅由已有工具轨迹和引用派生，不新增检索，不判断回答正确性。工具轨迹未记录可区分的执行结果，空返回不能解释为查无匹配。

## 兼容与成本

不新增接口、迁移、阶段类型、Worker 能力、模型请求、ASR 或截图提取；不改变 1.3 SYSTEM / prompt version、缓存配置、重放、剩余预算或 UNKNOWN 处理。笔记仅新增程序控制的摘要段落，不修改原回答或原结果 hash，不为源 JSON 增加未约定字段。

本轮复看此前已完成的真实样例，只读取既有结果和媒体。此前的一轮有限供应商验收已完成，未用额度不作为新一轮授权。
