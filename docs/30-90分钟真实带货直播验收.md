# 90 分钟真实带货直播验收

2026-10-27 至 2026-10-28，新的服装商家连续 90 分钟录播已完成分片上传、真实 ASR、30 窗商品分析、时间线发布、开发审核与三段正式 MP4 导出。756 条 ASR 在最终结果中恰好覆盖一次，累计 63 次文本请求、1 次 ASR 提交；两次失败和修复成本均保留。此结果证明该样本的流程和文件完整性，不代表商品识别准确率或通用处理时延。

## 输入与运行边界

来源为 niceioi 的[公开回放 BUfqqM](https://livebuy.tv/replays/BUfqqM)，从开头选择连续 5,400 秒、540 个相邻 HLS 分片，不拼接离散讲解片段。没有向模型提供 SKU、网页商品清单、商品跳转点或人工边界。完整内容未与所有历史素材做去重；它是新的商家开发输入，不是独立人工标注测试集。

| 分辨率 / 编码 | 360 × 640，H.264 / AAC |

下载收据逐片核验，5 次暂时超时保留事件记录，最终缺片为零。源文件经过明确归一化：编码参考文件的首个真实视频帧在 19/30 秒，前置 19 个纯黑帧使容器、音频和视频起点都为零。参考文件 161,980 个真实帧的 PTS 全量保留，归一化后共 161,999 帧；52:10 附近原有的 1/15 秒帧间隔继续保留，未填成理想恒定帧率。AAC 包的 payload、PTS 和 duration 与参考文件一致，完整音视频严格解码通过。这是显式处理的开发副本；上述证明相对于编码参考文件，不宣称逐像素等于原始 TS，也不把归一化后的零起点当作原始素材音画同步的独立证明。

## 真实执行与失败恢复

上传走正式持久分片 API：45 个分片，8 MiB / 片，最多 3 路并发。完整哈希、分片回执、发布后源文件、HEAD、首中尾 Range 和越界 416 均核验。

ASR 从本次新音频真实提交一次，生成 756 条转写，首条起点 4,560 ms、末条终点 5,399,980 ms。本轮未复用其他任务的 ASR；后续 SEGMENT 重试沿用本任务已经成功的 ASR 阶段，没有再次提交语音识别。

| SEGMENT 执行 | 实际结果 | 本次新增上游 TEXT | 累计 TEXT |
|---|---|---:|---:|
| attempt 1，v13 | 前两窗通过，第三窗重复类别，唯一修复仍失败 | 7 | 7 |
| attempt 2，v13.1 | 提供完整重复索引，但模型仍保留重复类别 | 1 | 8 |
| attempt 3，v13.2 | 补充有界原临时标签与可信核心语句定位，30 窗全部通过 | 55 | 63 |

第三窗失败来自耦合关系：独立发现给出多个细分类别，分类将其中多个概括成“上衣”等相同类别，却保留不同临时标签。v13.1 的整数索引反馈没有稳定修好；v13.2 在唯一修复中补充 `tmp` 数字标签与原核心语句 ID，要求模型重新判断并同步改写声明和分类关系。程序没有自动删除重复商品、投影无效行或代替模型生成预测，详见[逐句协议](./14-逐句分类协议.md#v132修复提示绑定原标签与可信语句)。

最终一次有 61 个逻辑调用：30 次独立发现、30 次分类和 1 次修复。其中 6 条初始请求通过请求身份和已存响应摘要校验复用原响应，新增 55 次上游 POST。累计 63 次是三次执行的唯一实际 POST 总数，包含两份后来未被接受的旧修复；没有把失败请求或旧尝试从预算中扣除。复用证据为实际请求记录、持久账本、输入重建和响应哈希的对应关系，本次没有截获完整的 `EXISTING` 预留回执，不能描述成有该接口轨迹。

63 次文本请求均 HTTP 200，累计 usage 为输入 289,292、输出 48,718、合计 338,010 tokens。ASR usage 返回 duration=5,372；该字段不是源文件精确时长。请求数和 usage 都不是人民币账单。

## 耗时的正确解释

90 分钟音频没有按播放速度识别两小时，本次 ASR 约 2 分 5 秒完成。MEDIA、ASR、三次 SEGMENT 和 TIMELINE 的执行 wall 累计约 20 分 57 秒，但中间发生开发修复、人工操作间隔和隔日服务恢复；不能把它写成无中断冷启动端到端时延，更不能外推所有两小时视频都能在同样时间完成。素材获取、归一化、开发测试、审核和审计耗时另计。

本机为 Ryzen 5700X、16 逻辑线程、约 32 GiB 内存；语音和文本推理为远程服务。本次没有依赖本地 GPU，也未更改视觉模型计费配置。

## 保留证据与仍存限制

旧 46 个公开资源及基线列出的 958 个文件均未改变。本任务的两份失败基线分别核验原 8/9 条模型账本及原尝试文件。Windows 普通扫描最初漏列长路径响应，审计首轮明确失败并保留；修正 QA 后仅按原基线已存在的 ledger.response_key/response_hash 补齐确切的 8/9 个响应，最终核验 54/88 个文件，未改原基线、生产记录或预算。

本地忽略目录 `data/runs/long-video-validation/` 保留阶段 proof、实际请求记录、分析/目录/请求核验、开发审核、导出核验、下载成片及失败保留报告；源获取证据在 `data/runs/long-video-source-discovery/`。媒体、原始模型响应、临时签名 URL 和凭证不提交公开仓库。

仍需继续改进：

- **视觉证据太稀疏。** 16 帧首末点为 168,767 / 5,231,267 ms，最大空档 337,500 ms。30 窗中 14 窗无采样；全片分布不等于持续视觉理解。后续应增加随时长变化的窗口最低采样覆盖及可见资源上限，再验证 OCR 耗时和收益。
- **类别粒度仍不统一。** 本次输出同时出现“上衣”“女士上衣”“针织上衣”等不同粒度名称。受限 ID 引用只提供可验证的归并机制，没有保证模型总能识别同义关系；41 条记录不能称为 41 个真实独立商品或 SKU。
- **边界跟随 ASR 语句。** 引用和时间映射已验证，但转场、返场、搭配顺带提及和起止语义仍需要全片标注。尚无 Precision、Recall、Temporal IoU 或边界误差的真实质量评分。
- **长任务的计算并行尚未完成。** 本次 ASR 为整文件异步提交，文本窗口顺序执行；持久 ASR 分片、RabbitMQ / Transactional Outbox 等路线不能写成已实现能力。

v13.2 修复本机全量 Python 为 **811 passed、98 subtests passed**，Ruff 通过。对应 [GitHub Python checks](https://github.com/Lshiii/LiveCut-AI/actions/runs/40529286267) 首次因 Ubuntu FFmpeg 包下载耗时超过 4 分钟失败，未进入测试；相同提交重跑后通过。该 CI 与本次真实模型运行分别提供证据，不互相替代。
