# 剪辑方案保存结果核对

2026-11-07。按需剪辑增加保存结果核对，处理保存请求已提交、但客户端没有收到可信回执的情况。核对使用已有读取接口，不新增模型或 ASR 请求。

## 原问题

用户以 r0 为基础修改方案并发出 PUT，服务端可能已保存为 r1，而响应在返回途中丢失。
旧实现会保留本地修改，却仍以 r0 作为保存基础；即使轮询已读到 r1，再点保存仍提交旧 base_revision，形成版本冲突。
因此，“未收到成功响应”不能直接解释为“保存没有发生”，仅显示失败或重复提交都不足以完成恢复。

## 核对与认领

保存未获得可信成功回执后，统一进入“核对保存结果”，先 GET 当前请求；不能仅凭错误码判断 HTTP 请求是否已经提交。
读取结果先经过来源与协议校验，再与当前已验证快照及列表缓存合并，使用有效的最新版本，不能让较旧 detail 回退版本。
纯函数 `intentSaveRecovered` 仅在以下条件同时成立时允许认领：

- 请求、分析、视频、完整来源及原句表一致，嵌套 plan 的来源、目标与权限身份保持一致。
- 两份快照均为 PLAN_READY，版本是有效整数；known 不早于草稿基础，incoming 不早于 known，且高于草稿基础。
- 状态版本不退步；同一 revision 的 plan_hash 不得相互矛盾。
- 本地方案与服务端方案经 intentPayload 正规化后全字段严格相同，包括选择、标题、区间顺序、排除项与证据。

认领后采用服务端修订更新本地 baseline 与 draftRevision，标记方案无需重复保存。
提示只说明“服务端版本与本页方案一致”，不声称能够证明该版本一定由前次 PUT 产生；另一客户端保存相同内容也可能满足条件。
已有确认记录可以随读取增加，核对本身不调用确认或导出。

## 不确定与冲突的处理

服务端内容不同或来源、权限、版本不满足条件时，保留本地草稿与旧保存基础，不自动覆盖、重发 PUT、确认或导出。
GET 失败时继续保留待核对状态，用户可再次读取；不会把读取失败当作旧保存未提交的证据。
GET 仍显示旧版本时，只代表本次观察到的状态，不能证明前次 PUT 永远不会完成；用户可稍后核对，或明确选择重新保存。
若重试遇到版本冲突，再次读取核对；不能凭旧版本读取结果跳过服务端的 base_revision 校验。
用户在等待期间继续编辑时，只有当前完整草稿确实与服务端相同才认领，不用较早发出的正文覆盖新编辑。

## 草稿保护与放弃

未知结果后，即使用户把字段撤回原 baseline，也仍需核对；仅凭本地看似“未修改”不能解除离开、创建、确认或导出的保护。
普通标签切换保持草稿和待核对标记，跨任务或请求切换继续经过现有守卫。
明确放弃时，从当前快照与已验证请求列表缓存中选择最新版本，再进行强制采用。
这样即使列表已读到新版本而 detail 读取失败，也不会拿旧快照 force 导致冲突后卡住放弃入口。
本次核对不代替用户的保存、确认与正式导出决定。

## 验证范围

11 项定向测试覆盖丢失响应后认领、已轮询到新版、不同内容、继续编辑、来源与权限变化、版本回退、确认记录，以及 reactive/deepfreeze 输入不变性。
前端全量 226 项测试、类型检查和生产构建通过。

隔离浏览器挂载真实 `IntentClipPanel.vue`，API 使用明确标识的本机合成状态，无真实 API 代理：

- 同内容已提交但断响应：轮询认出 r1，解除 dirty，不自动确认；一次点击产生两条同 base/body 的运输请求，其中一次提交、一次 409，不能据此宣称所有环境只发一条 wire PUT。应用没有自动重试循环。
- 同内容已提交且自然超时：合成服务记录客户端在约 15 秒关闭请求，之后轮询认出 r1；一次 PUT、一次提交，确认和导出均为 0。
- 具名 503 后服务端已有不同 r2：撤回标题到原 baseline、隐藏后返回、再核对，均保留本地标题和 r0 base，保持冲突保护。320px 宽下核对与放弃可操作，无组件横向溢出。
- 具名 503 且未提交：只读核对仍 r0 后，由用户明确再次点击保存，第二次 PUT 正常保存 r1，总提交一次。
- 具名 500 且列表领先：列表读取成功、详情连续返回 503 时，明确放弃仍能采用已验证缓存 r2，没有未捕获版本冲突。首次短故障观察被随后轮询覆盖，使用独立持续详情故障用例完成该项验证。

所有六个浏览器合成 run 的确认、导出请求均为 0，保存 pending 期间业务 GET 均为 0；另有五个合成 HTTP smoke 用例。真实页面仅临时编辑标题、GET 刷新核对和放弃，原标题恢复；未发真实业务 PUT/POST、ASR 或模型请求。真实数据库提交时连接丢失未进行破坏性故障注入；保存期间控件禁用，继续编辑竞态由纯函数测试覆盖。
以上结果不代表剪辑效率、恢复成功率或付费需求的测量结论。
