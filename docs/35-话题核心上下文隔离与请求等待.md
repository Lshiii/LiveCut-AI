# 话题起点协议、上下文隔离与请求等待

2026-10-29。针对同一 90 分钟直播在话题解析中的真实失败，调整内部模型决策为话题起点，并明确核心/上下文表达和请求等待策略。程序仍按原始 ASR ID 映射时间，公共结果契约、人工审核和正式导出含义不变。

## 由起点构造区间

`topic-chapters-v3` 每行仅要求 `start_utterance_id`、标题、摘要、关键词和续接布尔值；不接受模型提供 `end_utterance_id`。首起点必须等于核心首 ID，其余起点必须来自核心列表，并按可信源顺序严格递增、不能重复。程序按下一起点的前一个核心 ID 计算本段结束，最后一段结束于核心末 ID。

例如核心为 u1～u6，模型选择 u1、u4 两个话题起点，按此契约得到 u1～u3、u4～u6。起点是在选择语义切换位置；完整源语句分区由程序按定义构造，不额外请求模型填逐句归属。

连续仅指源语句 ID 顺序连续。相邻 ASR 句之间的静默可以在片段间留空，结束仍取本段最后一句的 `end_ms`，不会延长到下一段开始。跨窗整句按原中点规则归属，不截断或重复。模型不返回毫秒时间。

旧双边界字段被视为额外字段而拒绝；程序不会剥掉旧失败响应的 end 字段后将其当作 v3 成功结果。合法起点组构造的区间仍通过最终契约的精确覆盖和源时间校验。它避免结构上的漏配语句，不能证明模型选对了讨论点或摘要忠实。

## 输入边界

v3 沿用 v2.3 的输入隔离：当前可输出的核心语句放在 `transcript`，只用于理解的前文与后文分别放在 `context_before`、`context_after`，同时提供完整核心 ID 列表及首末 ID。

分组依据可信源 ID 顺序与已有核心归属，不重新按时间截断跨窗整句，不读取模型内容来决定边界。核心窗口仍为 10 分钟、上下文前后各 30 秒；它们控制请求输入，不决定最终话题长度。指令明确三个列表的职责，所有语句文本仍作为内容数据处理。

每窗最多一次格式修复；整组起点及续接标记独立验证通过时，提供只含可信源 ID 和布尔值的 `validated_topic_starts`，仅允许修元信息。改变起点、段数、顺序或续接标记仍失败；任何起点非法时不提供部分锚点。修复输入不反射模型自由文本。

续接仅允许在首行且已有上一话题时声明，类型必须是真正的布尔值。最终标题由程序保留首段标题，模型续接标题提议留在原响应和 accepted 文件中，不用这个未采用字段的措辞差异阻断整个任务；续接的语义判断和合并摘要仍需人工核对。

## 请求等待

话题请求读取等待上限调整为 300 秒，连接、写入与连接池等待采用较短有界值，并在每次派发前按当前阶段剩余时间收紧。历史 commerce 文本客户端保持原等待策略。

该修改不增加自动重试，不恢复 UNKNOWN_OUTCOME 的派发许可，不返还已预留额度，也不能保证模型在 300 秒内完成。阶段租约、总期限、迟到结果隔离和调用账本继续生效。
