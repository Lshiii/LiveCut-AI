# 问答覆盖与锚点上下文补全

2026-11-15，近一小时直播回放实测暴露两类问题：问答检索到效率解释后遗漏输入输出定义，并将局部未检到扩大为全片没有说明；引用剪辑冻结前后各一句，模型看不到更前面的定义，只能生成 NEEDS_REVIEW 候选。用户要求修复后用同视频完整复测。

## 新纯文本问答

新界面在后端声明 `/api/agent-capabilities/text-coverage` 支持协议 6 时，为新的纯文本提问显式提交 `qa_policy=coverage_v1`，无需额外用户开关。精确 404 兼容旧后端；其他能力查询失败不偷偷发送旧策略请求。视觉、分项证据、画面预查仍使用原策略。

Java 持久化策略并将其纳入请求指纹、阶段输入摘要与协议要求。旧 body 没有该字段时保持旧指纹和执行方式；原未决提交重放必须保留原 key/body，不能在升级后附加策略。V31 为旧行填充 `none`，不会重写成功回答或修改原模型账本。Worker 协议 6 和 `qa_policy` 必须互相匹配，旧 Worker 不可领取。

新执行提示为 `video-agent-coverage-v1`，要求按用户的问题逐项核对，区分直接证据、当前不足和外部常识，并在预算允许时补查缺失的定义与上下文。检索观察补充有界相邻原句，完整保留原句后才纳入可引用集合，不把截断内容或自动话题当作原视频证据。模型内部的覆盖检查不改公共回答格式：结果仍是 1.0 的正文、原句引用、工具轨迹和 provenance。

工具仍为 `search_transcript`、`read_context`、`list_topics`，最多 4 步。检索命中按相邻位置分组，公平分配完整原句预算；每组向前最多 8 句、向后 4 句，单向 120 秒，单次观察最多 18000 字符、累计上下文额度 36000 字符。新查询、结构修复和物理重试均计入本轮原文本预算，不能因内容不完整无限重试。`video-agent-v1` 的 SYSTEM、配置与缓存验证保持原语义。引用校验只能证明来源与取得路径，不能保证全部语义正确；实际覆盖效果必须用冻结参考复测。

## 引用剪辑上下文

新锚定请求冻结 answer-source 1.1，使用 `anchor-clips-v2` 和 `answer-anchor-context-v2` 索引摘要。每个锚点向前后逐层扩展，单向最多 8 句、120 秒；总量仍最多 72 句、12000 UTF-16 单元。优先保留明确选中的原句，逐层公平补充邻句；长度或时间限制阻断后，不跳过缺失句再接远处原文。

扩大的是模型可阅读范围，不是直接把窗口当作成片。模型仍需选最小而完整的解释区间；每个选中锚点必须保留，不得用别处相似表达替换。自动候选必须处于实际展示的连续范围；遇到截断、不明指代或解释仍不完整时，保留 NEEDS_REVIEW，而不是提升为 FOUND。

旧 answer-source 1.0 保持前后各一句、旧 v1 prompt/index/hash 和缓存；恢复旧请求不升级冻结版本。新的 1.1 请求要求 Worker 协议 5。V30 扩大协议可登记集合，但具体任务仍严格绑定自己的版本。前端接受两种来源并按版本核对摘要。

普通保存、人工选用、确认与导出权限保持原流程。自动 FOUND 候选初始也不勾选；用户明确选用、保存和确认后才能导出。NEEDS_REVIEW 仍需独立复核，不能用技术校验冒充内容审核。
