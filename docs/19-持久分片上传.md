# 持久分片上传协议

2026-10-25，实现与本机真实验收完成。实现沿用 Java/MySQL 和共享存储，上传完成不自动创建分析或调用模型。参考来源和边界见 [路线](./18-参考项目与分片上传路线.md)。旧整文件 POST /api/videos 保持兼容。

## 固定接口

- `POST /api/uploads`：必需 Idempotency-Key（1～128 个字母、数字、点、下划线、冒号或连字符），JSON 为 `{original_filename,size_bytes,content_hash}`，其中 content_hash 是原文件完整 SHA256 的小写 64 位十六进制。文件限有效显示名称的 MP4、非空、最多当前配置上限（不超过 1 GiB）。同键同标准化输入返回原会话，换输入返回 409 IDEMPOTENCY_CONFLICT。
- `GET /api/uploads/{id}`：返回持久快照；已完成会话返回同一 video，不因活动会话 TTL 到期失去完成回执。
- `PUT /api/uploads/{id}/parts/{index}`：application/octet-stream 原始字节，必需 X-Chunk-SHA256。片索引从 0 开始，服务端验证精确长度、实际 SHA256，最终片长度由总文件大小计算。相同内容重复片不重复计数；不同内容 409 PART_CONFLICT。MERGING 期间不接收新片，完成后相同片重放不重新创建临时片。
- `POST /api/uploads/{id}/complete`：缺片返回 409 UPLOAD_PARTS_MISSING；合并冻结后返回 202 及 MERGING 快照，客户端查询 GET。合并已在执行时复用当前执行；COMPLETED 返回 200 和同一最终 video。
- `DELETE /api/uploads/{id}`：放弃未完成会话并回收临时文件；不能删除已发布视频。COMPLETED 返回 409 UPLOAD_ALREADY_COMPLETED。客户端暂停只停止发送，不调用 DELETE。

公开快照字段固定如下（不存在内部 token、磁盘 key 或 Idempotency-Key）：

```json
{
  "id":"UUID",
  "status":"UPLOADING",
  "original_filename":"sample.mp4",
  "size_bytes":123456,
  "content_hash":"64 lowercase hex",
  "chunk_size":8388608,
  "total_parts":1,
  "received_parts":[{"index":0,"size_bytes":123456,"sha256":"64 lowercase hex"}],
  "received_bytes":123456,
  "state_version":2,
  "expires_at":"UTC instant",
  "video_id":null,
  "video":null,
  "error_code":null
}
```

status 为 UPLOADING、MERGING、COMPLETED、FAILED、EXPIRED；COMPLETED 的 video 为现有 VideoAssetResponse、video_id 为 video.id，其他状态均为空。received_bytes 是持久确认字节，不包含尚在网络中传输的数据。服务端默认片为 8 MiB，客户端必须使用会话返回值，不能写死续传片规格；测试可以使用小片。total_parts 需有上限，防止极小配置产生海量记录。state_version 防止并发回包令页面进度倒退。

## 状态与持久化

MySQL 保存会话、分片、容量预留。初始化固定目标 video_id 和文件身份。短事务先登记会话内固定索引的接收文件并获取接收锁，再在事务外流式接收、校验，最后在短事务内按会话锁定并原子发布片和回执。接收锁持续到注册或丢弃结束；放弃/到期时仍有接收者则保留容量，待其退出后重试清理。已确认片重放只流式校验实际字节，不再创建接收副本。分片文件不得覆盖不同的已确认内容。活动会话默认 24 小时过期，只有自己的临时路径可以清理。

complete 冻结输入并获取合并执行代次/token/租约；流式合并和 SHA 校验在数据库事务外执行，不长期持有数据库锁。有界合并执行器及扫描器恢复过期的合并租约，旧执行不能发布新结果。完整字节数、各片摘要、整文件 SHA、MP4 头均通过后，短事务再次验证执行权，发布固定 UUID 来源，将 video_asset 注册与会话 COMPLETED 一起提交。文件已发布但事务响应不明时保留源文件，恢复时校验并采用同一固定来源，不重新生成 video_id。

默认最多 8 个活动会话、4 GiB 暂存预留、6 个并发接收及 1 个并发合并。每个活动会话预留声明文件大小的 3 倍，覆盖分片、每索引至多一个接收副本和合并文件；排队合并保存在 MySQL，不使用无界内存队列。过期清理、放弃、分片发布和合并收口遵守一致锁顺序；清理永远不删除 videos/ 下的已发布来源。完成回执不依赖临时片存在，清理失败不回滚成功且继续占用预留，扫描器重试回收。永久的完整性/格式错误进入 FAILED，公开安全错误码，不输出路径或原始异常。

合并/清理使用会话级文件锁，接收使用索引级文件锁，锁文件身份保留以避免删除后重建导致互斥失效。同 JVM 在打开 channel 前登记路径、关闭时幂等释放，避免部分平台关闭第二个 channel 意外释放原生锁。这里面向同主机共享本地卷；跨主机网络文件系统与多副本部署尚未验收。完成回执和少量锁元数据保留，生产化仍需另定历史记录保留策略。

## 客户端

先在 Web Worker 中以 2 MiB 小块增量计算完整 SHA256，不把整个文件读入内存，使用固定版本 hash-wasm 4.12.0；每片摘要使用有界 Blob 数据计算。内容摘要与文件元数据用于本地恢复键，初始化前保存幂等键，丢失初始化响应也能找回原会话。

最多三个分片并发，每个请求最多退避重试三次网络/408/429/5xx；每次恢复以服务端快照为准。状态查询失败保留续传记录；明确 EXPIRED 才能新建会话，仅有幂等键时的初始化 410 也作明确过期处理且最多重建一次。刷新后重新选同一文件，摘要不同不能混接旧片。上传暂停终止本轮网络任务并保留进度，重新开始/放弃有明确语义。MERGING 显示独立处理状态，上传达到 100% 不代表视频来源已注册。浏览器拒绝 localStorage 时仍可当前页暂停续传，但明确提示刷新恢复可能不可用。此功能没有实现跨会话“秒传”。

后端错误沿用 `{error_code,message,retryable,request_id}`。关键码：INVALID_UPLOAD_ID、UPLOAD_NOT_FOUND、UPLOAD_EXPIRED、INVALID_PART_INDEX、INVALID_CHUNK_HASH、PART_SIZE_MISMATCH、PART_HASH_MISMATCH、PART_CONFLICT、UPLOAD_NOT_WRITABLE、UPLOAD_PARTS_MISSING、UPLOAD_RECEIVE_BUSY、UPLOAD_CAPACITY_EXCEEDED、UPLOAD_ALREADY_COMPLETED、UPLOAD_FAILED。异步合并排队体现在 MERGING 状态中。

## 验收

Java 全量 `verify`：116 项，0 失败/错误/跳过，其中新增 19 项真实 HTTP/MySQL 上传集成测试和 1 项跨 JVM 文件锁测试。覆盖并发/重复片、错片长度与摘要、缺片完成、并发 complete、租约失效/旧执行、发布后回滚、真实提交成功后丢失 ACK、到期清理与合并竞争，以及慢 PUT 与 DELETE/TTL 竞争时暂存配额不能提前释放。独立 Java 子进程验证同 JVM 失败抢锁、旧 owner 重复关闭均不能释放现有原生锁。

前端 14 项逻辑测试、`vue-tsc` 和生产构建通过。包含有界增量摘要、同元数据不同内容、乱序/丢响应、暂停恢复、状态查询失败、仅存初始化幂等键时过期、JSON 响应体读取超时与本地存储不可用。真实浏览器另行发现并修复默认 fetch 绑定问题，模拟逻辑测试不能代替浏览器验收。

真实开发录像为 159,834,576 字节，完整 SHA256 `4868ad1821fb0887123416f3619abb80549fa93d7e309cc9d92dd1fa25618d32`，8 MiB 分片共 20 片：

1. 通过实际页面选择录像，QA 代理仅延迟 Java 已成功接收后的响应。服务器保存索引 0、1、2 后暂停，浏览器尚未收到这些确认。
2. 刷新页面、重启 Java 后，同一会话仍为 3 片/25,165,824 字节。重新选择原文件，页面显示恢复 3 片；代理请求记录验证只发送索引 3～19，共 17 片，原 3 片没有重传。
3. 合并完成注册为原预留视频 `36857d09-0066-409a-b296-12929a55e654`；下载后的完整 SHA 与原片一致。HEAD 200、首 32 字节 Range 206、越界 Range 416 均通过，ffprobe 验证 1800.017 秒 H.264/AAC；临时片/合并文件清理完成。
4. 第二个会话在真实合并临时文件已写入 65,536 字节时终止已核实的开发 Java 进程。停机后只读数据库仍为 MERGING/attempt 1，预留来源尚未发布，确认命中合并中断窗口。重启后扫描器以 attempt 2 恢复，同一预留视频 `2e64e05d-4b1c-4eae-895b-3b7f8a362c25` 完成；完整 SHA、Range、媒体探测与暂存回收均通过。故障验收临时将合并租约设为 10 秒，默认仍为 90 秒。
5. 首个完成回执在再次重启及临时片清理后逐字段相同；原先 4 个分析任务、2 个导出批次快照及清单摘要保持不变。没有创建新的分析任务，也没有新增模型调用。
