# 连接恢复与未知模型调用排查

2026-10-29。针对“无法连接服务”残留及一份 90 分钟新分析失败，分别核对页面读取状态与实际 Provider 调用。两种问题不能混为同一个恢复操作。

## 页面连接恢复

现场曾出现列表已恢复、顶部显示“服务已连接”，但旧的网络错误仍显示；URL 中有任务 ID，首次详情请求失败后却停在新建分析界面。

原因是详情失败进入操作错误字段，后续列表成功只清连接错误；首次详情只在挂载时读取一次。现在列表连接错误、详情连接错误和操作错误分开保存，成功读取只清对应连接错误。

详情首次发生网络错误或超时后，记住任务 ID 和当前选择版本。后续列表刷新成功时每轮最多补读一次，最多自动补读三次；用户切换任务、切换视频、新建分析或卸载时取消恢复。审核有未保存内容、正在提交，或其他操作仍在进行时暂停补读，旧异步结果不能替换新选择。创建、取消、分析重试等写操作不自动重放。

404、500、业务错误和契约错误继续作为操作失败显示，不进入网络恢复队列，也不会因为列表恢复而被清除。

验证：前端 56 项通过，TypeScript 检查与 Vite 生产构建通过，差异检查通过。另在隔离 HTTP 夹具上实际用浏览器验证：

- 初次列表和 URL 详情连接主动断开；点击刷新后列表恢复，页面自动补读 URL 任务并清掉网络提示。
- 详情返回 404 / `JOB_NOT_FOUND`，列表刷新成功后该错误仍可见，没有自动重试详情。
- 真实工作台重载后能读取失败任务详情，网络错误提示消失。

夹具仅验证网页恢复逻辑，不连接真实模型、不生成视频、不代表识别质量验收。开发证据与截图位于被忽略的 `data/runs/service-recovery-20261029-222703/`。

- 第 2/9 个窗口请求在约 120 秒后发生传输异常，未取得响应；本地窗口状态为 `uncertain`，持久调用账本为 `UNKNOWN_OUTCOME`，没有响应文件或可验证的文本任务 ID。

这次不是 ASR 失败、不是文本预算耗尽，也没有证据把它认定为内容检查拒绝。服务进程后来停止属于另一个已观察到的环境状态；现有证据不足以确定停止原因。

沿用现有约束：未知调用不自动重新派发、不返还额度、不改写为成功。直接重试阶段会先复用成功响应，然后在未知请求处停止，无法证明重复提交免费或安全。
