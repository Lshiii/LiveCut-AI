# CI 媒体依赖安装的有界等待

2026-10-26。仅调整 Python Actions 中 FFmpeg 依赖准备，不改变业务代码、锁定依赖、真实媒体测试或禁止跳过测试的检查。

## 已观察到的失败

同一实现提交 `daa3e5f` 的功能分支运行 `40326379617` 成功，安装步骤约 18 秒、整个 job 约 47 秒；主分支运行 `40326833847` 停在 Install FFmpeg，耗尽 15 分钟 job 上限后 cancelled，尚未执行测试。此前文档提交也有一次相同阶段超时，重跑才成功。

原步骤直接执行全源 `apt-get update`，没有步骤或 APT 网络超时。现有状态证据能确定耗时发生在媒体依赖准备阶段，未取得足够安装正文，不能断言具体哪一个源或网络环节故障，也不能把 cancelled 算作测试失败或通过。

## 调整

- 先检查配置路径中的 ffmpeg、ffprobe 都可执行且 `-version` 成功，满足时复用现有工具。
- 否则要求 Ubuntu 24.04 的 `/etc/apt/sources.list.d/ubuntu.sources` 存在，仅使用该 Ubuntu 源准备所需包；缺失时明确失败，不静默跳过。
- 设置每项网络等待 15 秒、下载重试 2 次、锁等待 30 秒；安装步骤整体最多 4 分钟，保留整个 job 的 15 分钟上限。
- 更新错误按失败处理，保留 `--no-install-recommends` 和最终两个工具的版本检查。正常的软件包完整性验证不关闭。

这里减少的是不必要的外部源参与，并限制失败等待，不保证依赖服务永远可达或安装必然成功。失败后应查看当前运行终态与错误，不能仅因观察超时重复启动另一轮。

## 验证范围

本机通过 YAML 解析、Git Bash `bash -n`、差异检查；临时 shell 桩验证正常工具复用、损坏工具不误用、缺 Ubuntu 源明确失败。没有在 Windows 上执行真实 APT；远端 Ubuntu 安装与完整测试以本提交的 Actions 结果为准。

其余 workflow 步骤保持原样：固定 Python/uv、`uv sync --locked`、Ruff、包含真实 FFmpeg 的完整 pytest，以及对测试报告中任何 skipped 用例的明确拒绝。模拟桩不是实际媒体测试，不能替代远端执行。Python 工作流位于 [.github/workflows/python.yml](../.github/workflows/python.yml)。
