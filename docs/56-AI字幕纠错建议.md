# AI 字幕纠错建议

2026-11-07。把重复错词的人工查找继续推进为 AI 辅助校对：模型读取一批已保存字幕及受限原句上下文，必要时搜索转写，提出修改或回听建议。它没有重新识别音频，也没有确认语义事实；用户逐条核对后，采纳只进入本页文字草稿。

## 产品流程

1. 在成片“字幕校对”中进入“AI 校对建议”。有未保存修改时先保存；新请求只使用已保存版本。
2. 选择起始字幕、文本请求次数上限和可选的术语提示。创建冻结当前字幕版本的校对会话，再明确开始本批。
3. 每批最多 20 条完整字幕，字幕与原始转写的 UTF-16 长度合计不超过 6000；显示实际覆盖范围。用户可选择下一批遍历长稿，不隐式自动发起全稿请求。
4. AI 可以直接回答，也可以调用 `search_transcript`、`read_context` 查找依据；最多 4 个工具步骤，使用原有预算、有限修复与故障恢复机制。
5. 纠错项显示本轮输入、建议文字、理由和原视频时间的原句依据；不确定项只提示回听，不能直接采纳。没有建议不表示整段语义已被认证。
6. 采纳前再次核对成片、字幕保存版本、来源及目标当前文字。任一选中条不匹配时整批拒绝，不覆盖后续手改；成功后回到校对列表，用户仍需保存、复核并确认。

本页采纳复用最近一次文本替换的会话撤销记录，与普通批量替换共享一条最近记录；保存、采用快照、恢复或关闭后清除。原始 ASR、时间、逐条核对标记和既有成片保持独立。

## 任务与资源边界

复用 `agent_session` / `agent_turn` / `AGENT_TURN` 所有权及账本，新增会话类型 `CAPTION`，普通视频问答保留 `VIDEO` 的原协议。专用阶段 `CAPTION_PROOFREAD` 映射到 TEXT 资源，Worker 需明确注册该能力；旧 SEGMENT 执行器不能误领后发普通问答请求。Python CLI 与 PowerShell 入口支持只运行此能力。

每轮独立文本预算 1～24 次，默认 4 次，格式修复及自动重试计入原上限；ASR 上限为 0。取消、租约、attempt/run_token、UNKNOWN 账本和成功响应重放沿用现有执行边界。失败后可明确创建新一轮及独立预算，旧账本和字幕保留，不自动加预算。

每次新请求或单次格式修复前，Worker 只读核对当前 turn/session/job/stage 的预算、RUNNING 状态及 attempt。工具额度按中央剩余次数与真实传输层最大物理尝试数收紧，为最终回答保留调用机会；较高预算仍最多 4 步工具。预算暂不能核实时关闭工具，只用已提供的证据回答；明确取消或 attempt 变化立即终止。最终每次派发仍由 Java 账本校验，不能靠本地余量绕过上限。

每次请求的工具额度、预算快照和完整 messages 摘要先落盘，缓存重放保持原 payload，不按后来已消耗的预算改写旧请求。完整旧结果仅在来源、调用状态、响应摘要与最终回答一致时只读复用；缺少可核对状态的旧半成品明确停止，旧文件与账本保留。

会话冻结完整已保存 CaptionSnapshot、原视频/转写/成片摘要及其版本。每轮把实际批次上下文存入持久记录，Worker 不接受浏览器自造时间或原句。初始上下文包含本批全部来源原句；相邻完整原句按预算加入，原文总量最多 12000 UTF-16 单元，不截断后冒充完整依据。工具观察继续使用单次及累计上限。

`caption_snapshot_hash` 是建会话时完整快照的 canonical JSON SHA256；它用于结果身份绑定。后续同版本确认可改变确认元信息，但不能改变冻结内容身份。新的保存版本不被旧建议覆盖，旧会话及记录仍可只读查看。

长稿可有超过 100 批校对：CAPTION 会话最多 10000 轮，VIDEO 仍限 100。专用会话响应只带最近 20 轮并显式返回总量和偏移，旧轮次通过分页读取，不把当前页误称全部历史或全稿覆盖。

## 接口与结构

| 接口 | 行为 |
| --- | --- |
| POST `/api/exports/{exportId}/clips/{clipId}/caption-proofread-sessions` | `caption_revision`、`caption_content_hash` 与 Idempotency-Key，冻结已保存版本 |
| GET 同路径 | 仅本成片的 CAPTION 会话列表 |
| GET `/api/caption-proofread-sessions/{id}` | 冻结来源、最近 20 轮、`turns_total`、`turns_offset` |
| GET `/api/caption-proofread-sessions/{id}/turns?offset=0&limit=20` | 历史轮次分页，limit 1～100 |
| POST `/api/caption-proofread-sessions/{id}/turns` | `offset`、`max_text_calls`、可选 `instruction` 与 Idempotency-Key，明确新建一批 |
| GET `/api/caption-proofread-turns/{id}` | 状态、预算、批次、建议和程序映射的引用原文 |
| POST `/api/caption-proofread-turns/{id}/cancel` | 取消当前轮，拒绝迟到结果 |

结果使用独立的 [`caption-proofread.schema.json`](../contracts/caption-proofread.schema.json) 和 `caption_proofread` manifest 产物，不放宽原 `agent_answer` 契约。[合成例子](../fixtures/caption-proofread.example.json)只用于协议验证。

模型只选择本批 cue ID、建议文字及证据 ID；程序映射 `before`、coverage、原句和时间。模型必须返回与本批完全相同且源序一致的已读 ID；每条字幕最多一个建议。`CORRECTION` 必须有不同的非空建议，`UNCERTAIN` 的 after 必须为 null。建议证据只能来自初始上下文或本轮工具实际返回的原句，不能因存在于整片转写就引用。

Python 与 Java 分别验证来源、批次、文字及观察证据；公开 DTO 从冻结原句映射可读依据。前端再次绑定来源、版本和 before，保留原字段；未成功、来源不符、旧版本及不确定项不能采纳。幂等请求标识跨本页刷新保留；未知回执先核对或按原标识查询，不因超时断言请求没有发生。

面板复用成片级列表 GET 核对接口可用性，只有严格源绑定的合法响应才开放新会话、新批次、取消及原键核对。仅列表 404 提示当前入口不可用，承认来源地址、代理或服务版本的可能性；网络、5xx 和无效 200 保持临时故障，可手动重新检查。Session/Turn 的业务 404 不参与这个判定。故障不清 UNKNOWN 标识、不更换幂等键，已有本页验证过的建议继续可看、可采纳到本地草稿。

格式修复仍最多一次，不放宽协议。提示同时给出 CORRECTION 与 UNCERTAIN 的完整 JSON 示例，并根据具体校验规则解释修正字段；例如 UNCERTAIN 的 after 必须是 JSON null，不能复写原字幕、空字符串或字符串 "null"。内部提示修订进入缓存指纹，公开结果契约仍为 caption-proofread-v1。模型两次返回不合规内容时保留失败和实际账本，不丢掉非法项后伪造成功。
